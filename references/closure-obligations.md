# 隔离器件与电源反馈：缺什么、怎么补、怎样算通过

隔离和补偿容易被更宽泛的“已核连接/应力”结论掩盖。计划按已确认的功能电路生成独立成员，
不是靠报告词语匹配发现问题：

| 规则 | 必查内容 | 单独的解决条件 |
|---|---|---|
| PRO-D02 | 跨隔离网络与器件用途 | 无错误跨接 |
| PRO-C03 | 实际工作条件是否在各器件允许范围内 | 实际电压、频率和环境满足所选型号的绝缘要求 |
| PWR-C04 | 最小导通/关断与输出电容条件 | 实际时序与电容条件适用 |
| PWR-C15 | 反馈模型、补偿配置、角点稳定性/动态 | 计算结果或厂家适用条件证明当前补偿配置满足稳定性及动态要求 |

PRO-C03逐个记录变压器、光耦/数字隔离器、跨接电容等实际隔离成员。
短时耐压、目标绝缘类别、无直流跨接均不能独自关闭元件工作资格；PCB距离/实物试验另列。
PWR-C15不要求每个线性供电都建立PWM模型：无反馈环可据拓扑NA；内部补偿可用厂家适用条件证明，
不强制索取本来不需要的外部R/C。实际Bode测试属于后续验证，补偿选值或模型缺口属于本阶段。

## 结果合同

这两条规则的结果必须有 `obligations`，键与计划的 `closure_contract.obligations` 完全相同。
每项包含 `review_result`、具体 `rationale`、`evidence`。INSUFFICIENT项用 `request_keys`
指向该行真正需要的 `input_requests`；同一资料可以支持多个义务，但不能拿不相关请求凑覆盖。
行结果保留最差义务，不能因连接正确而PASS，也不能整体转成阶段NA。
不适用义务须写 `inapplicability_basis` 并给实际拓扑/用途出处。

PRO-C03还须有 `qualification_members`，按计划 `object.refs` 覆盖每个实际隔离器件。
每个器件记录 `review_result`、`working_basis`（实际工作应力/条件，未知明确写未知）、
`qualification_basis`（准确变体的资格及条件）、`comparison` 和 `evidence`。
没有器件清单时保持未完成/资料缺口，不能用空表宣称通过。

## 任务边界

相关 `input_requests` 和所属任务均写 `closure_domain`：PRO-C03为
`isolation_qualification`，PWR-C15为 `loop_stability`。
这些任务所有选中的请求必须属于同一解决条件；不能把RCD/短路SOA等请求一并塞入补偿任务。
不同电源电路的补偿也分别建任务（例如PFC与反激）；同一电路不同工况可共用一项，不能仅因同属loop_stability而合并不同环路。
其他检查行可共享真正的补偿缺口，但须用 `request_keys` 明确选中该分支，并给相同领域。
这不要求“每条检查一个任务”，也不按文字相似度合并。

## 报告怎么写

标题点名器件或电源环路，每件事只写三点：缺什么、怎么补、怎样算通过。
“隔离资格”改成“该器件能否满足实际电压、频率和环境下的绝缘要求”；
“环路关闭条件”改成“该电源的反馈怎样才算稳定”。不要额外重复通用的“必须核清”清单。
完整的逐器件记录、模型和判据仍保存在台账，现有校验继续检查是否遗漏。

- 隔离器件：写出哪些变压器、光耦或跨接电容缺实际工作条件或厂家允许条件；
  取所选型号资料，逐个对照；所有实际条件满足相应绝缘要求才算通过。短时耐压值不能代替长期工作范围。
- 电源反馈：写明是哪一路电源，缺功率级/反馈模型、哪组补偿参数或哪段工作范围的计算；
  补相应模型或厂家适用条件；在已有要求覆盖的输入、负载及温度范围内满足稳定性和动态要求才算通过。
  已有数值标准就直接写数值；未定的明确指出，不能为报告好看编出裕量要求。

同一器件或同一环路在多条规则、多种工况下重复索取同一资料，只列一次并写全适用范围。
同一份资料可支持多个器件时可合并取得资料的动作，各器件的不同限值仍分别写出。
PFC 与反激可以共用厂家资料，仍分别说明如何判定各自通过。
仅整理报告时，只精简表达和重复动作，不新增检查、试验或资料要求，也不因已有表格可展开就增加任务。

脚本只核合同覆盖、状态一致和请求归属。工作应力的推导、厂家条件是否适用、请求内容是否真实，
仍由审查者核定；填齐字段不构成电气正确的证明。
