# 执行一致性：从局部证据到整体主张

本页不新增电气限值，判据仍以 catalog 和各专用引用为准。遇到共享控制网、多个供源/装配状态、
功能汇总或共享整改任务时，下结论前按下面四条核对。适用范围先按原始资料固定，不从想要的结论倒推。

## 1. 先列对象 × 状态 × 路径

- 按受控需求、当前装配和逐端点连接列出实际状态与独立外部来源；同名电压轨不代表同一来源。
- 共享 EN/RESET：逐个列接收者、控制器、钳位和无源支路。全网保证要用所有支路在该状态下的阈值、
  负载和供电情况；一颗接收者的漏电、单极 RC 或典型曲线不能代表全网。
- 已证实可达的反例判 FAIL 并写明角点；只有条件估计时保留 INSUFFICIENT（余量记 ESTIMATE），不称保证上界。
- 采购与功耗按每个适用工况的实际端点电压差/电流计算并计入公差：不漏掉外部电源更高的状态，
  也不给所有电阻机械套用最高轨电压。整改 RC 还要核最终高/低电平和每个接收者的跨越时刻。

## 2. 局部 PASS 不扩展为路径或系统 PASS

- 先写清已证主张的边界，再沿供能、信号和返回路径查旁路。例：IC 的 Ioff 只证明该引脚，
  外接上拉、保护管或体二极管绕过 IC 时要另查被夹持/浮空和电阻功耗。
- 有限能量或已知功能失效不证明器件免于损伤；已判 P1 的功能缺陷不能遮掉独立的潜在 P0 分支。
- 输入缺功能名或解析资格失败时，全板输入资格仍不通过，但缺口只影响确实依赖该事实的判据：
  已用原生端点和官方脚义证明的窄连通项可独立审结，不因全板 NO_GO 把每条都改成 INS。

## 3. 父项按判据和真实依赖导出

- 先分清父项核的是覆盖还是电气功能。覆盖项（如 REQ-Q07）只答成员是否已审，不复制子项 FAIL；REQ-Q07 由 `derive_rows.py` 按同类电路各行写出，不手填；绑定行全为 NA 时脚本不写，由审查员填并写依据。
- 功能父项列全部必需成员：有成员已确认 FAIL 时保留该 FAIL 及全部关闭依赖，不因另有缺口降回 INS；
  无 FAIL 但有成员未闭合时不能 PASS；只修好一项时写明部分关闭。
- NA 要有独立的适用性依据，不是让父项 PASS 的占位值。

## 4. 每个整改/移交任务只解决自己的问题

- 把任务的前提、采购条件、操作和验收逐条对回实际缺口及来源要求。例：补功能名/脚义记录的完成标准是
  准确记录、原生重导和物理/BOM/NC 核对，不附带无关的供应商、SOA 或额定条件；真实选型另列任务。
- 板级防护与系统认证分开核本轮承诺：系统波形、PCB、热/EMC 写 HANDOFF；未承诺的整机记录不阻断
  已成立的本体判据。已承诺的系统边界或本体电气前提仍须审，不能为减少 INS 而移交。
- 共享任务可共享证据，不共享无关模板；每组移交的对象、数值、条件、接收方和复验范围要对应。
