# 审查 ASG 交付的设计

> 读者：审查员（被审对象是 ASG 的交付目录时）。

ASG 的交付目录里，SR 只读下面这些文件，其余都是设计方记录：

| 文件 | 用途 |
|---|---|
| `设计方案/` 下唯一的根 `.kicad_sch` 和其他图页 | 被审原理图 |
| `设计方案/netlist.xml`、`设计方案/schematic.pdf`、`设计方案/BOM.csv` | KiCad 原生网表、图面、BOM |
| `设计资料/需求基线.md` | 需求基线：原始需求条文，加上设计过程中用户在需求澄清里给定或采纳的条文、降额等级 |
| 原始需求文件（另外提供时） | 与需求基线一起读；两者有出入时以需求基线里的澄清条文为准 |

需求基线里已定的澄清是用户（或任务书授权的代答人）定下的需求，不是设计方的结论：照它审，不再就同一件事重问；审查认为某条定得不合理时写成意见，不自行改用别的取值。
它里面标明是假设（用户暂缓）的澄清不是需求：对应的条文不审，在报告里列入“本次不审的范围”。降额等级照需求基线写的等级。
交付目录里没有 `设计资料/需求基线.md`（早先的交付）时，向用户要原始需求文件和澄清结果，不从 `record/` 里取。

`设计方案/` 是一个 KiCad 工程，里面还可能有 PCB 环节的 `.kicad_pcb`、`.kicad_dru` 和它自己的文件，这些不属于原理图审查，不读。早先交付的目录里这个文件夹叫 `原理图/`，内容相同，照样读。

`设计报告.md` 和 `record/` 下的设计网表、需求清单、计算、自检与图面审阅记录都不读、不引用：SR 从原理图、需求和原厂资料独立取证和复算。ASG 自检的通过结论不迁移；前一轮审查的通过结论也不直接沿用，改版按 [改版复审](quick-review.md#改版复审) 做。
原理图上看不出、只写在设计文档里的事实写成移交项请设计方确认。
