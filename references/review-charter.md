# SR 的目的与审查纲要

## 目的

依据当前需求、设计数据和器件保证条件，判断原理图在规定工况下能否实现预期功能，
识别有证据的连接、参数、保护及需求偏离，给出可执行的修改与复验依据，
支持设计迭代并判断原理图是否具备冻结进入 PCB Layout 的条件。

审查效力来自找对问题、说明依据、避免漏查和误判、使修改能够闭环；规则条数、台账大小
和格式检查通过率不是目的。用户明确的任务范围和已确认需求优先；缺项应说明实际影响。

## 七项纲要

| 纲要 | 要回答的问题 | 审查落点 |
|---|---|---|
| G1 需求与功能符合 | 要求的功能、接口和性能是否落实到电路？ | 需求逐条追溯，功能存在性、接口角色、数量和定量指标；需求不清先澄清 |
| G2 器件与连接正确 | 实际器件、物理脚、装配与端到端连接是否正确？ | 准确型号与变体、脚义、极性、装配选项、源/负载和返回路径；核对对端 |
| G3 工况下的功能与性能 | 启动、运行、掉电等适用状态下，电源、控制与信号能否按要求工作？ | 电源建立、复位、时钟、接口、模拟链、默认态、顺序和恢复；考虑硬件与固件依赖 |
| G4 参数裕量与器件应力 | 保证值、公差及工作范围是否满足指标和器件能力？ | 电压/电流/功耗、有效容量、时序、误差、稳定性及适用 SOA；模型和角点由实际条件确定 |
| G5 保护与异常响应 | 需求内的故障、防护及隔离是否有效，动作与恢复是否合理？ | 过压/过流/反接/浪涌/注入、隔离和保护协调；计入器件内置保护，不强加固定保护拓扑 |
| G6 实施、测试与下游约束 | 原理图是否可落实和验证，必要布局、热及测试约束是否明确移交？ | 图纸与物料表达、调试/测试节点、可执行的布局和散热约束；接收与验证要求有据 |
| G7 证据覆盖、改进建议与复验闭环 | 是否查全且结论有据，不通过项是否明确如何改进、如何复验？ | 从实际输入枚举，证据对应对象/工况/判据，缺口如实保留；每项不通过均有明确改进建议与关闭条件，修改及依赖复验、版本可追溯 |

G1–G6 是工程目标，G7 支持这些目标。内容域 DOC/DEV/PWR 等用于组织对象，
A/E/T/C/D/V/Q/H 用于选择方法，都不增加一套独立检查。
规则主归属及数量由 [规则总表](check-catalog.md) 从 `scripts/catalog.py` 生成；
主归属用于维护，每条规则可以同时支持其他纲要。功能包只复用成员规则，不新增判定层。

## 判定与范围

- 判断“实际电路是否满足适用要求”，不判断“是否照抄常见电路”。固定值、默认态、
  保护级数与外部元件必须来自本器件/模式/项目要求；参考设计偏离可有据成立。
- 在原理图内可判定的连接、应力、保护和配置须完成；真实电气缺口不能转交下游来放行。
  PCB 实际间距、SI/PI、EMC、热实现与生产验收由相应阶段完成，SR 输出所需约束，
  并核实外部结果引起的原理图修改。[边界矩阵](verdicts-and-release.md#边界矩阵) 是具体划分。
- PASS/FAIL 由适用证据支持；未知保留具体缺口，不适用有依据。自动扫描提示、
  覆盖检查与格式对账不能替代电气结论，也不能把待核事项计为已确认缺陷。
- 同一次审查中完成判断、证据核实和必要的反证检查；自动对账收尾。
  共用证明、补证和修改动作只写一次，独立电气结论分别判断；正文使用精简报告模板。

## 不通过项必须产生可执行建议

每个 FAIL 必须说明具体位置、违反的判据与影响，并给出改什么、怎么改、参数/接法依据、
连带检查和通过标准。INSUFFICIENT、未决需求及未完成移交也须明确下一步动作与关闭条件，
但不冒充已确认缺陷：缺数据就指出所需参数和取得方法，缺设计就给出可落地的设计/计算路径。
不能只写“不通过”“待验证”“优化设计”或“参考手册”。参数尚未确定时给条件方案及确定步骤，
不编造精确数值。共用动作可合并一次并链接全部受影响检查，不因此合并独立结论。
明确建议属于审查交付的必要组成；具体字段复用 [修改说明](report-and-remediation.md) 和已有任务记录，
不另造一套填表。没有建议与复验条件的不通过项不能作为完成的审查交付。

## 用纲要指导进化

新增或修改规则时，在现有规则定义/评测中回答三个问题，不新增项目填表要求：

1. **解决什么问题？** 指向上述主纲要，说明实际误判、漏检或边界混淆；优先修正已有规则，
   不把某个型号的案例常数推广为全局要求，不因一个案例增加重复检查。
2. **怎样判断有效？** 明确适用对象、工况、判据和最小证据；提供能区分正确电路、真实缺陷
   与证据不足的案例。涉及执行代码时运行相应回归；纯措辞/说明修正核对生成的计划和引用即可。
3. **是否值得保留？** 比较漏检、错误通过、误报、不必要待核及审查负担；
   合成基准只证明其覆盖模型。不能靠增加未知项、模板限制或重复审查提高表面“严格度”。

维护映射在目录加载时检查遗漏、重复和过期 ID；新增规则未归属即报错。此检查只证明规则有归属，
规则内容是否合理仍须对照上述目的阅读。规则或判据变化后，进行中的项目按
[规则指纹与重新审查](plan-and-results.md#五规则指纹与重新审查) 完整重审。当前规则的全面对齐记录见 [2026-10-07 对齐审计](../docs/audits/2026-10-07-review-charter.md)。
