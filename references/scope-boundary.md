# 原理图审查边界与结果状态

本 skill 的准出对象是**原理图设计数据**。通过表示“原理图可以冻结并进入 PCB
Layout”，不表示 PCB 已通过审查，也不表示整板可以投板生产。

设计迭代另报告本轮任务；阶段选择、根因归并和纯下游验证的移交条件见
[design-iteration.md](design-iteration.md)。原理图前提不足不能转移为样机验证。

## 四种审查结果

| 状态 | 含义 | 对准出的影响 |
|---|---|---|
| PASS | 原理图与 datasheet/需求证据充分且符合 | 无 |
| FAIL | 原理图证据已证明存在问题 | P0–P3 按 severity-calibration.md 处置 |
| INSUFFICIENT | 本项适用，但缺会改变本判据的具体输入，无法定判 | 阻断级项未补齐或未书面接受时阻断 |
| NA | 经适用性判断后确认不适用 | 无；必须写明不适用依据 |

NA 不得代替 INSUFFICIENT。A/B/C 只用于独立的 `evidence_confidence` 字段，
A/B/C 定义以 severity-calibration.md 为准；C 表示结论证据未齐，对应 INSUFFICIENT。

适用性及证据尺度见 [最小充分证据](evidence-proportionality.md)。已有资料尚未分析的事项
列“审查待完成”，不得称为外部证据缺失；不满足通用模板本身不构成电气缺陷。

## 独立 HANDOFF 动作

`HANDOFF` 不是审查结果，而是原理图审查形成的下游动作。每项检查先给上述四种
结果，再独立记录：

- `required`：是否需要移交；
- `state`：`OPEN` / `ACCEPTED` / `VERIFIED`；
- `receivers`：PCB Layout、SI、EMC/Test、结构、系统集成方/模块使用者等明确接收方；
- `constraint`：由原理图证据导出的可执行约束；
- `verification`：下游如何关闭。

集成约束（模块本体范围内导出、须由外部主机/负载/系统满足的条件）也用 HANDOFF 记录，接收方为系统集成方或
模块使用者：需求指定了须接收约束的集成方或产品时 `required: true`，按常规阻断准出；开放模块没有指定集成方时
`required: false`，仍填 receivers/constraint/verification 并在报告“集成约束”类别列出，不计缺陷、补证任务或移交计数。

因此同一项可以是“原理图连通性 PASS + PCB 阻抗约束 HANDOFF OPEN”，也可以是
“原理图拓扑 FAIL + 修复后仍需布局 HANDOFF”。约束未形成或无接收方时仍阻断准出。

## 自动产物到报告状态的映射

| 自动扫描/证据计算的中间产物 | 报告落点 |
|---|---|
| FINDING | 专家复核确认后为 FAIL；有反证排除后为 PASS，并保留排除依据 |
| CANDIDATE | 判据未补齐前为 INSUFFICIENT；补齐资料取证/需求证据后转 PASS 或 FAIL |
| 自动验证 PASS | 仅该输入对象和判据的候选通过，专家核实模型/覆盖后才能写最终 PASS，保留 check id、计算和 citation |
| SKIPPED / pending | 适用但缺输入为 INSUFFICIENT；有依据确认不适用才是 NA |
| 依赖布局、实测、结构或生产落实的要求 | 独立 HANDOFF，写接收阶段、约束和验证方法；不替换本项结果 |

因此 Lint 命中不等于 FAIL，Lint 零命中也不等于 PASS；最终状态由专家审查（方式 T/C/D/V/Q）
在证据链上复核后给出。

## 边界矩阵

| 域 | 原理图内直接判定 | 形成 HANDOFF | 本 skill 不判定 |
|---|---|---|---|
| 电源 | 拓扑、轨压、EN/PG、反灌、时序逻辑、器件额定值 | 大电流网、去耦位置、散热要求 | PCB 压降、PDN、实测温升 |
| 高速接口 | TX/RX、P/N、电平/共模兼容、端接和耦合拓扑 | 阻抗、等长、间距、过孔与回流要求 | 眼图、串扰、板级 SI 仿真 |
| EMC/ESD | 防护器件选型、方向、连接和泄放拓扑 | 摆放顺序、靠近连接器、屏蔽接地 | 辐射/传导结果与认证 |
| 测试 | JTAG/调试接口和必要观测节点的电气连接 | TP 类型、禁分叉网、邻近地要求 | ICT 可达性、夹具与覆盖率 |
| 安规 | 隔离器件、耐压等级、跨域连接 | 高压分区与间距要求 | PCB 实际爬电/电气间隙 |
| 器件 | MPN、符号、引脚（按手册引脚定义的编号或名称）、封装字段和外围参数一致 | 特殊封装/摆放要求；焊盘编号与封装映射 | 焊盘、钢网、装配工艺 |
| 可靠性 | 可由原理图和规格确定的电压/电流/功耗应力 | 热敏器件和验证条件 | 完整 FMEA、鉴定、筛选、寿命试验 |

完整供应链、结构、PCB DFM、SI/PI、EMC、热和生产测试属于独立质量门。来自这些
活动的**原理图整改输入**仍须回到本 skill 做网表复验。

## 热相关审查边界

原理图审查检查热相关的电气前提，并向 PCB/结构提供散热约束；完整热设计不在本 skill 的验收范围。
按下表拆分判据，不把“电气选型合理”和“实际温升合格”合成一个 PASS/FAIL：

| 阶段 | 检查与输出 | 判定边界 |
|---|---|---|
| 原理图 | 声明负载/占空比/故障状态下的损耗与额定值、温度等级和参数保证条件、适用 SOA、必要温度检测/保护连接与门限 | 用适用证据判断电气符合性；真实电气前提缺失仍为 INSUFFICIENT，已证实违反仍为 FAIL |
| 约束移交 | 位号、工况、损耗上界或负载谱、允许结温/壳温及依据、SOA 起始温度限制、适用的环境温度需求 | 写入独立 HANDOFF；温度约束是下游设计输入，不是对实际温度的测量或保证 |
| PCB/结构/样机 | 铜皮、热过孔、散热器、接触热阻、风道、闭壳耦合、实际结温/热点温度与温升验证 | 下游完成设计和验证；原理图报告只引用可追溯的外部结果，不自行签署热设计通过 |

环境温度、壳温和结温分别记录，不直接互换。手册热阻和温升电流带有封装、测试板、安装及
散热条件；不能直接当本板实测值。可在适用且有依据的模型下估算或反算散热要求，写明假设，
不把条件估算包装成实际温升结论；保守上界越限本身也不证明实际超限。

新计划把电气判据和下游验证分开：下游热验证只记 HANDOFF，不另造必须热测试才能 PASS 的
原理图检查，不因缺 PCB/结构模型或热测试给已完成的电气检查追加 missing_inputs。
不能仅因“还未测温”要求换件或判原理图不准出。若温度条件确实影响电气判据，先按允许范围
定界并形成约束；无法确定适用额定值、保证条件或可执行约束时，保留具体电气缺口，不用移交掩盖。

| 情形 | 处理 |
|---|---|
| 已按声明工况完成 LDO 损耗与额定核对，尚无 PCB/闭壳模型 | 电气判据独立给结果；损耗和允许温度移交，不声称结温通过 |
| 不知道 LDO 最大负载，无法确定损耗与所需器件能力 | 记录负载/需求缺口，仍需原理图阶段补齐 |
| 已有证据证明功耗超过适用额定，或工作轨迹违反适用 SOA | FAIL；不能用“等热测试”替代整改 |
| 只有室温 SOA，且高温条件影响保护判据 | 查适用降额/模型或反算允许起始温度；无法支持判据时 INSUFFICIENT，不假定全温有效 |
| 滤波电感 RMS 电流满足手册温升电流规格及适用条件，但未测板上温度 | 只确认规格比较，板上温升独立移交 |
| 外部热验证发现过温，需要改拓扑、器件或保护门限 | 引用外部证据形成原理图整改输入，对改动做电气复验 |

对历史混合判据先保留原始记录，再以更正依据将电气检查与热 HANDOFF 拆开，重建计划并重新
绑定结果，记录旧检查到新判据/移交的映射。不能批量改 PASS/NA、删检查或仅修改绑定消除阻断。
确实保留为独立下游检查的旧项，按 design-iteration 的下游验证协议处理。

冻结要求必需约束已形成且真实交接，不要求下游热验证已完成：HANDOFF 的 ACCEPTED
表示接收约束，VERIFIED 才表示下游验证完成。电气 PASS + HANDOFF ACCEPTED 可以进入
原理图冻结；HANDOFF OPEN 的交接阻断应单列为流程事项，不计作电气缺陷。日常设计仍可继续。

## 准出用语

允许：

- 原理图准出，可进入 PCB Layout。
- 原理图有条件准出：无开放 P0，已完成全部检查，剩余阻断项已有有效接受记录并落实约束。
- 原理图不准出：存在开放 P0、未接受的阻断 FAIL/INSUFFICIENT、覆盖未完成或必需 HANDOFF 未接收。

禁止：

- 整板可以投板。
- SI/PI、EMC、热、DFM 已通过（除非另有对应审查证据，本报告只作外部引用）。

未关闭关键前提只能不准出，不能以“有条件准出，待后续再关闭”提前放行。接受不改变实际 PASS/FAIL。
