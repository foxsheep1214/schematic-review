# 结论、分级、阶段与准出

本页统一回答：每项检查给什么结果、缺陷定几级、本轮做什么、原理图能否冻结。
准出对象是**原理图设计数据**：通过表示“原理图可以冻结并进入 PCB Layout”，不表示 PCB
已通过审查，也不表示整板可以投板生产。适用性和证据尺度见 [最小充分证据](evidence-proportionality.md)。

## 1. 四种检查结果

| 状态 | 含义 | 对准出的影响 |
|---|---|---|
| PASS | 原理图与资料/需求证据充分且符合 | 无 |
| FAIL | 原理图证据已证明存在问题 | 按 P0–P3 处置 |
| INSUFFICIENT（证据不足） | 本项适用，但缺会改变本判据的具体输入，无法定判 | 阻断级项未补齐或未书面接受时阻断 |
| NA | 对本产品不适用（`NOT_APPLICABLE`）；或纯下游判据本阶段不判（阶段 NA，`APPLICABLE` + `na_reason: OUTSIDE_SCHEMATIC_STAGE`） | 不构成电气缺证；须有依据。阶段 NA 单独统计，保留产品待验及移交闸门，见[纯下游验证项](#纯下游验证项) |

- NA 不得代替 INSUFFICIENT；未执行项不能填 PASS，也不能用 NA 消失。
- 已有资料尚未读算的事项记“审查待完成”（REVIEW_INCOMPLETE），不得称为外部资料缺失。
- 不满足通用模板本身不构成电气缺陷。

**自动产物到最终结果**：Lint 命中不等于 FAIL，零命中也不等于 PASS；最终状态由审查者
（方式 T/C/D/V/Q）在证据链上复核后给出。

| 自动扫描/保证值核对的中间产物 | 最终结果 |
|---|---|
| FINDING | 复核确认后为 FAIL；有反证排除后为 PASS，保留排除依据 |
| CANDIDATE | 判据未补齐前为 INSUFFICIENT；补齐后转 PASS 或 FAIL |
| 自动验证 PASS | 仅该对象和判据的候选通过；审查者核实模型/覆盖后才能写最终 PASS |
| SKIPPED / pending | 适用但缺输入为 INSUFFICIENT；有依据确认不适用才是 NA |
| 依赖布局、实测、结构或生产落实的要求 | 纯下游行阶段 NA + HANDOFF；原理图前提单独判，不替换其电气结果 |

## 2. 严重度 P0–P3

先分开回答四个问题：事实是什么（连接、贴装、参数）？违反哪条适用判据？在什么工况下
影响什么功能？每个主张的证据是否充分？不能把“事实很确定”直接传给未验证的灾难后果，
也不能因后果不确定而撤掉已确认的规格不满足。

| 等级 | 判据 | 典型情况 | 准出处置 |
|---|---|---|---|
| P0 致命 | 危险应力/损坏风险、关键安全保护缺失、必需启动或核心链路确定断开 | 高压与普通外设直连；唯一供电路径确定不贴 | 必须修复并复验；不能通过接受放行 |
| P1 严重 | 必需功能/性能或推荐工作保证不满足、强制接口条件违反 | 全角不能保证启动 strap；端口少于需求 | 修复，或有权责任方明确接受后有条件准出 |
| P2 一般 | 局部非关键功能、裕量、维护测试或数据一致性问题 | 非关键故障指示不可用；误导性字段 | 处置/记录；违反项目必需验收条件时仍阻断 |
| P3 建议 | 已符合要求后的可选优化、低影响图纸卫生 | NC 属性残留、名称改进 | 择期处理 |

- 表内是定级起点，不按器件或规则自动赋级。需求关键性、发生条件、外部暴露、独立硬件保护写入定级理由；
  不凭“低概率”降级绝限风险，不编造概率/RPN。必需功能/性能偏离通常至少 P1。
- **保证范围即判据**：VIL(max)/VIH(min) 是保证范围。必须读 0 的节点最坏电压超过 VIL(max)，
  已足以确认“不能保证低电平”，通常 FAIL/P1，无需等到实物必然读错。典型翻转点、单板调通或
  室温一次测试不能证明全温/批次保证。
- 实测与分析冲突时复核版本、BOM、测点、时序、仪器和模型；可撤回“必然失效”的过强表述，
  未满足保证的事实仍保留。“must/shall”确定约束性质，但不单独决定 P0；“recommended”纳入
  受控需求或影响正常工作时按影响定级。
- **先核允许的故障终态**：若受控需求允许适用破坏性单故障下的永久安全失效，不将该故障下的
  任意内部器件损伤自动判P0，也不能要求所有器件保持正常额定作为唯一关闭路径。分别核要求的保护动作、
  火灾/触电/危险输出及安全防护是否成立。允许损伤不等于已证明损伤安全；有实际危险路径或关键安全保护
  缺失仍可P0。正常工作、无损恢复测试和寿命要求不随之放宽。
  撤回任意故障电压/长期平均功率所支撑的P0时，不自动改P1：重查剩余实际判据；必需功能保证缺口可P1，
  已充分成立的判据PASS，真实危险路径成立则保留P0。记录为何更高等级本次没有依据或已被排除。
- 一个根因关联多个检查时按唯一 finding 统计，不把 20 个 FAIL 算作 20 个缺陷。
  已满足要求的可选优化用 `kind=IMPROVEMENT`，不能写 FAIL。

## 3. 证据置信度 A/B/C

- **A**：结论能由已验证输入直接重现（网表集合、官方限值与可复算区间等）。
- **B**：有可定位依据和适用条件的工程推导，推导链公开。
- **C**：关键身份、拓扑、要求或工况缺失；对应 INSUFFICIENT。PASS/FAIL 不得以 C 为依据。

证据来源（netlist / schematic / BOM / datasheet / requirement / calculation / test）另记，A/B 不是来源类型。
例：确认一颗电阻标 DNP 为 A；装配 BOM 与图面冲突时，“实物必定不贴”是 C——可分别记录
“装配数据冲突”的 FAIL 和“因此会断电”的 INSUFFICIENT（潜在 P0）。

### 证据不足的危险度分类原则

`INSUFFICIENT` 的中文展示名统一为**证据不足**，报告中写作“证据不足（INSUFFICIENT）”，其他结果同样写“通过（PASS）”“不符合（FAIL）”“不适用（NA）”；机器状态不改。其危险度用已有
缺口的 `severity.level`（潜在影响等级）P0–P3 表达，包含电气危险及功能影响，**不是失效概率或安全认证等级**。
按**有物理依据、且尚未排除的最严重后果**定级。资料缺失量、证据置信度 C、器件类别和取得资料的难度
不决定等级；禁止整批默认 P1，也禁止把“尚无参数”本身当作 P0 的依据。

#### 判定步骤

1. **限定判据与工况。** 绑定当前对象、贴装/状态和受控要求，说明缺哪个输入、会改变哪个判断。
   覆盖需求规定的正常、启动/掉电及适用故障工况；不自行加入需求已排除的误接或无限能量情形。
   先拆开连通、工作保证、绝限耐受、保护协调和下游实测，避免一个宽泛判据把所有子项都升为最高级。
2. **建立后果路径。** 从实际连接、供能/信号路径和器件限值说明：缺口若取不利但可信的值，
   在该工况下怎样影响器件、负载或功能。区分不可逆损坏/危险暴露、核心链路断开、必需性能失保、
   局部非关键影响和可选优化。可保留条件分支，不把“可能”写成“已经发生”。
3. **核排除依据与独立保护。** 计入有据的输入上限、电流/能量限制、钳位、默认关断和替代路径。
   用于排除严重后果的保护必须有适用门限、时序、耐受和故障可用性的证据，且不依赖同一未闭合前提；
   只有“装了保险/TVS/有软件保护”或同一未知 OTP 中的另一功能不能证明风险已被排除。
   不要求不存在的通用保护，也不因缺 PCB/整机实测而撤掉已有原理图边界。
4. **选择最高可信后果的等级。** 按下表定级，并解释为何更高等级的路径不适用于本判据或已被排除。
   可信最坏上界越限但边界过宽，仅表示仍需收紧分析，不能据此判已确认 FAIL；“边界过宽”须指出哪个输入取得松、
   收紧后可能翻转结论。设计已定的值在手册保证值下算不过（所需顺从电压高于保证最小值、结温超过含项目降额的限值），
   不是边界过宽，是保证要求未满足，判 FAIL；
   不适用/无界模型或任意参数探索的越限结果不能单独支持潜在 P0。
   拓扑、工作点及器件边界支持的绝限/关键保护缺口可以支持潜在 P0，无需先证明实物必然损坏。
   连对象关键性和后果路径都未厘清时，先追踪或澄清，报告标审查未完成，不强行发布有确定等级的完整结论。
对于动作速度相关的后果，先按[动作窗口与裕量](evidence-proportionality.md#保护动作窗口与裕量)形成比较。
缺少全温最大值、尚未实测或某个时间没有精确数值，均不能单独决定P0/P1及冻结影响；
已证实的绝限违反、无有效保护路径及决定保护有效性的关键未知仍按实际后果保留。

5. **单独记录冻结影响与闭合条件。** 写清排除后果或调整等级需要的最小证据、取得方法和复验判据。
   是否阻断冻结、何时处理、是否用户暂停分别记录；不能用“暂不处理”降低危险度。
   补证/改版后重判，升级或降级均留具体依据，原等级不是永远不变的标签。

#### 等级边界

| 潜在等级 | 本项缺口涉及的可信后果 | 定级所需依据与边界 |
|---|---|---|
| P0 | 危险应力、不可逆器件/负载损坏、关键安全保护失效；或真实配置分支使唯一必需供电/核心链路断开 | 有实际暴露/能量或唯一链路，以及相关额定/保护判据；该缺口直接妨碍排除后果。高压器件名称、任意尖峰假设或普通启动保证缺失本身不足以定 P0 |
| P1 | 必需功能、启动/恢复、协议、精度/动态性能、寿命或全工况工作保证不足 | 缺口直接影响受控必需目标；尚未建立本判据通向 P0 后果的路径，或该路径已有独立排除依据 |
| P2 | 局部非关键功能、维护测试、物料/图纸数据一致性或一般交付缺口 | 说明影响局限及为何不影响关键电气/必需功能保证。不能把未明额定、保护身份或关键配置统一降为“资料问题” |
| P3 | 可选优化或低影响图纸卫生的判断尚缺依据 | 基础必需要求已有通过证据，缺口只影响优化选择。必需验收证据缺失不属于 P3 |

#### 后果类别（`severity.class`）

每条缺口在 `severity.class` 写后果类别，等级由类别决定，`validate_review.py` 检查二者一致：

| consequence_class | 含义 | 潜在等级 |
|---|---|---|
| `DAMAGE_OR_HAZARD` | 安全危险：火灾、触电、绝缘跨域器件、危险能量、用户端口过压，或使一项安全保护失效 | P0；须在 `severity.hazard_path` 写明是哪条路径：`FIRE` / `SHOCK` / `INSULATION` / `HAZARDOUS_ENERGY` / `PORT_OVERVOLTAGE` / `PROTECTION_LOSS`；该路径已有独立排除依据时写 `exclusion` 后可为 P1 |
| `CORE_LINK_LOSS` | 唯一必需供电或核心链路可能断开 | P0（同上，须写 `hazard_path`，有 `exclusion` 可为 P1） |
| `COMPONENT_DAMAGE` | 某个器件可能不可逆损坏，但不打开上面任何一条危险路径（例如二次侧低压开关管短路 SOA、同步整流管交叉导通、信号脚 ESD 损伤） | P1（版本 2 新增；版本 1 没有这一类，当时这类缺口只能写 `DAMAGE_OR_HAZARD`） |
| `REQUIRED_FUNCTION` | 必需功能、启动/恢复、协议不保证 | P1 |
| `PERFORMANCE_OR_LIFE` | 精度、动态性能、寿命或全工况保证不足 | P1 |
| `LOCAL_OR_DATA` | 局部非关键功能、维护测试、物料/图纸数据一致性 | P2 |
| `OPTIMIZATION` | 只影响可选优化 | P3 |

先选类别再得等级：选不出类别说明后果路径还没理清，按上文第 4 步先追踪。
"可能损坏器件"不等于危险：器件损坏要成为 P0，必须说得出它打开哪条危险路径（`hazard_path`）。
常见的 P1 而非 P0 情形：二次侧低压开关管在端口短路下的 SOA（有熔断器/初级 OCP，终态是坏机不是火灾）；
同步整流管换流不及时的交叉导通（同上）；CC/D± 信号脚的 ESD 耐受（损伤控制器，不危及用户）；
已有锁定式 OVP 路径、只缺动作时序数据（除非已算出停能前端口可达的能量/电压超过受控上限，才是 `PORT_OVERVOLTAGE`）——
此时类别仍写 `DAMAGE_OR_HAZARD` + `hazard_path: PORT_OVERVOLTAGE`，用 `exclusion` 写明是哪个锁定式 OVP 及其门限出处后降为 P1；
不能改写成 `COMPONENT_DAMAGE` 或 `REQUIRED_FUNCTION` 把路径藏起来（`PORT_OVERVOLTAGE_GRADED_BELOW_P0` 提示）；
熔断器分断能力：IEC 60127 高分断（H，1500 A）熔断器用于插墙电源时按额定分断能力核，不要求电网可用短路电流数据。
仍是 P0 的情形：绝缘跨域器件（变压器、光耦、Y 电容）的长期工作电压/环境条件缺证（`INSULATION`）；
保护元件本身额定不明且其失效会让一次侧故障持续（`FIRE`/`PROTECTION_LOSS`）；端口可能出现超出受控上限的电压或能量（`PORT_OVERVOLTAGE`）。报告“数字一览”按类别计数，
结论里的资料缺口按待办（同一原因合并）计件，同时注明涉及的检查条数。

同一对象可以有不同等级：触点电流耐受、被动端子映射、接口协议配置不是同一个判据。
复合判据暂无法拆开时，按其中最高可信后果分支定级，并明确是哪一分支；共同根因可归并补证任务，
不把最高等级复制给所有关联检查。置信度仍为 C，不因潜在 P0 提高为 A/B，也不编造概率/RPN。
录入时回查本项关键性：主控必需时钟起振、必需稳压轨有效输出电容/稳定性缺口不能套成普通物料 P2。
关键磁件的饱和/温升保证缺口也按其所在供电链的必需功能评估，不能因补证对象是
物料参数而套成 P2；损坏或唯一链路断开的潜在 P0 则仍须独立路径与边界证据。
断电输入注入或输出预偏置反流若有实际路径及适用绝限/损坏依据，保留其条件性潜在 P0 分支；
不因电压低、风险尚未实测或功能电路统一 P1 而抹去，也不把该等级移用于正常运行的窄方向项。

#### 边界例子

| 缺口与已知边界 | 分级判断 |
|---|---|
| 实际反激功率路径及开关耐压已知，漏感/吸收响应未知，无法排除适用关断工况下不允许的器件超限损坏或不安全终态 | 可定潜在 P0；指出具体开关、尖峰路径及适用要求。允许永久安全失效的单故障另核安全后果，任意输出电压敏感度或“变压器缺手册”不能独立定级 |
| 控制器实际供电谷值未知，缺口直接影响 UVLO/必需启动保证；本项没有独立建立损坏或唯一链路断开的配置分支 | 潜在 P1；如果另查出栅极应力或不安全默认态，分别评估其后果，而不把本项自动改成 P0 |
| 非关键故障指示的物料字段不一致，已核不参与供电/保护且关键功能已保证 | 潜在 P2；若该器件实际上承担唯一保护，重新按保护路径分级 |
| 核心要求已通过，只缺哪种图纸命名更便于维护的依据 | 潜在 P3；不能用这个例子降级关键物料身份或制造验收缺证 |

每个开放项的 `severity` 写明 `affects`（受影响功能）和 `consequence`（条件性后果，同时是定级理由），
工况写在开放项的 `scope`，冻结影响依据就是开放项的 `closure`。
具体缺口与证据由开放项的 `what`、功能的 `conditions`/`evidence` 和行的 `binding` 定位。共用物理路径可以引用同一分析，
但必须说明它与本项判据的关系；一个高风险对象上的所有检查不因此自动成为 P0。
`consequence` 包含“缺口→后果路径→独立保护/排除依据→所选等级”；调整等级所需证据和复验动作写在
`acquisition`/`spec` 或 `closure` 里。没有后果路径的“风险未知/参考手册”不构成定级理由。
把“该规则涉及可靠性，未知时可能影响功能”等泛化文字换成当前对象的实际物理因果：未知参数如何
经哪段供电/信号/保护路径改变哪项受控功能，已知限值与独立排除依据是什么。单纯回显对象、工况、
判据或加一句“潜在 P1/P2”仍不构成后果链。依据不足时先完成追踪，不能为了完整字段或 `valid=true`
强行接受等级；未完成追踪的审查只交进度。合并补证任务时保留每行独立后果与真实缺口。

FAIL/INSUFFICIENT 默认阻断；只有阶段允许暂留的 P2/P3 才写 `"blocking": false`。P0/P1 写了也照样阻断。
工作时点和是否暂停由任务记录管理，不从等级推出；用户暂停任务不等于电气影响降低。
结构校验只能发现字段漏填及已编码的不一致，不能证明路径、保护独立性或工程定级正确。
`quality_screening` 另给两类提示（不阻断）：不同判据共用完全相同的 `consequence`
（`REUSED_IMPACT_ACROSS_SCOPES`；同一任务独占的几条判据共用一句后果是该任务的分析，不提示），
以及至少 10 项证据不足中九成以上落在同一潜在等级（`UNIFORM_POTENTIAL_SEVERITY`）。
收到提示时逐项复核后果路径，确属共用分析的写明它与各判据的关系。
写法提示（不阻断）：位号与数值粘连（`REF_GLUED_TO_VALUE`，如 R12100°C）、通过条件里带三位以上小数的算例中间值
（`OVERPRECISE_CLOSURE_VALUE`，如 257.121uA；写手册/标准边界和条件，不写样例结果）。
另有两类定级提示：同一句带 P0–P3 的话作为 ≥10 行、≥3 条规则的定级理由（`TEMPLATED_SEVERITY_REASON`），
以及同一规则 ≥10 行证据不足全部同级（`UNIFORM_SEVERITY_WITHIN_RULE`）。还有一类通过理由提示：同一段话（去掉“见功能判定…”前缀、
对象回显和“（依据 …）”后缀，需求编号不计）判通过了问不同问题的行（`TEMPLATED_PASS_RATIONALE`；同一器件的身份、脚表与引脚处置算一个问题，
需求行按需求方面分），例如一段图纸核对或电路走线描述关掉了灌电流、应力和指示灯亮度。设计迭代阶段三者只提示；
`schematic_freeze` 阶段三者计入放行阻断（`valid` 不变），定级类须逐行按本对象后果路径重新定级，通过理由类须逐行写出比较了什么、对照什么，才能放行。
批量录入脚本不得用一句固定兜底语给全部证据不足定级。
审查者按上述步骤核理由与本项判据；补齐证据后重新判断，可能成为 PASS 或任意等级的 FAIL。
需求未定（REQUIREMENT_OPEN）的检查不填等级，改由 [需求澄清项](requirement-clarifications.md) 记录决策时点和冻结影响。

## 4. HANDOFF 与集成约束

HANDOFF 不是检查结果，而是原理图审查形成的下游动作。每项检查先给四种结果之一，再独立记录：

- `required`：是否需要移交；`state`：`OPEN` / `ACCEPTED` / `VERIFIED`；
- `receivers`：PCB Layout、SI、EMC/Test、结构、系统集成方/模块使用者等明确接收方；
- `constraint`：由原理图证据导出的可执行约束；`verification`：下游如何关闭。两者都要写出具体位号、网络和数值，
  脱离检查行也能读懂，不写“本行”“本项”。

**只交本设计特有、由原理图审查算出来的要求。** 自动计划只给电解电容寿命行（DEV-C02 寿命行）预填热设计移交，不预填其他 HANDOFF；审查中确实得出一条
后续环节必须照做、否则原理图结论不成立的具体要求时，才在该检查行加 HANDOFF，例如“测 Q1 漏极峰值应低于 800V”
“变压器漏感不超过主电感的 0.5%”“USB D+/D− 按 90Ω 差分走线（数据功能已启用时）”。
“回路尽量短、去耦就近、注意散热、差分等长”这类通用布板常识不是原理图审查结论，不写 HANDOFF，
也不得把它当成原理图审查做过 PCB 审查的依据。

同一项可以是“连通性 PASS + 具体阻抗要求 HANDOFF OPEN”，也可以是“拓扑 FAIL + 修复后仍有具体布局要求”。
ACCEPTED 表示接收约束，VERIFIED 才表示下游验证完成。HANDOFF 随原理图作为清单交出，**不卡冻结**：
OPEN 不进 blockers；填 ACCEPTED/VERIFIED 时须附真实记录，Agent 不代填。

**集成约束**（模块本体范围内导出、须由外部主机/负载/系统满足的条件）也用 HANDOFF 记录，
接收方为系统集成方或模块使用者：需求指定了须接收约束的集成方时 `required: true`，随图交出、不阻断准出；
开放模块没有指定集成方时 `required: false`，仍填 receivers/constraint/verification，在报告“集成约束”
类别列出，不计缺陷、补证任务或移交数。

### 边界矩阵

| 域 | 原理图内直接判定 | 形成 HANDOFF | 本 skill 不判定 |
|---|---|---|---|
| 电源 | 拓扑、轨压、EN/PG、反灌、时序逻辑、器件额定值 | 大电流网、去耦位置、散热要求 | PCB 压降、PDN、实测温升 |
| 高速接口 | TX/RX、P/N、电平/共模兼容、端接和耦合拓扑 | 阻抗、等长、间距、过孔与回流 | 眼图、串扰、板级 SI 仿真 |
| EMC/ESD | 防护器件选型、方向、连接和泄放拓扑 | 摆放顺序、靠近连接器、屏蔽接地 | 辐射/传导结果与认证 |
| 测试 | 调试接口和必要观测节点的电气连接 | TP 类型、禁分叉网、邻近地 | ICT 可达性、夹具与覆盖率 |
| 安规 | 隔离器件、耐压等级、跨域连接 | 高压分区与间距要求 | 实际爬电/电气间隙 |
| 器件 | MPN、符号、引脚（手册引脚定义的编号或名称）、封装字段和外围参数 | 特殊封装/摆放；焊盘编号与封装映射 | 焊盘、钢网、装配工艺 |
| 可靠性 | 可由原理图和规格确定的电压/电流/功耗应力 | 热敏器件和验证条件 | FMEA、鉴定、寿命试验 |

来自 PCB、SI/PI、EMC、热和生产活动的**原理图整改输入**仍回到本 skill 做网表复验。

### 热相关审查边界

原理图审查只检查热相关的电气前提，并向 PCB/结构提供散热约束；不把“电气选型合理”和
“实际温升合格”合成一个 PASS/FAIL。

| 阶段 | 检查与输出 | 判定边界 |
|---|---|---|
| 原理图 | 声明负载/占空比/故障状态下的损耗与额定值、温度等级和参数保证条件、适用 SOA、温度检测/保护连接与门限 | 用适用证据判电气符合性；真实电气前提缺失为 INSUFFICIENT，已证实违反为 FAIL |
| 约束移交 | 位号、工况、损耗上界或负载谱、允许结温/壳温及依据、SOA 起始温度限制 | 写入独立 HANDOFF；温度约束是下游设计输入，不是实测保证 |
| PCB/结构/样机 | 铜皮、热过孔、散热器、风道、实际结温与温升验证 | 下游完成；原理图报告只引用可追溯的外部结果 |

- 环境温度、壳温和结温分别记录，不互换。手册热阻和温升电流带有测试板与安装条件，不能当本板实测值。
- 不为下游热验证另造“必须热测试才能 PASS”的原理图检查，不因缺 PCB/结构模型或热测试给已完成的
  电气检查追加缺口，也不能仅因“还未测温”要求换件或判不准出。
- 温度条件确实影响电气判据时，先按允许范围定界并形成约束；无法确定适用额定值或保证条件时，保留具体电气缺口。

| 情形 | 处理 |
|---|---|
| 已按声明工况完成 LDO 损耗与额定核对，尚无 PCB/闭壳模型 | 电气判据独立给结果；损耗和允许温度移交 |
| 不知道 LDO 最大负载 | 负载/需求缺口，原理图阶段补齐 |
| 证据已证明功耗超过适用额定，或工作轨迹违反适用 SOA | FAIL，不能用“等热测试”替代整改 |
| 只有室温 SOA，且高温影响保护判据 | 查适用降额/模型或反算允许起始温度；无法支持判据时 INSUFFICIENT |
| 外部热验证发现过温，需改拓扑、器件或保护门限 | 引用外部证据形成原理图整改输入并做电气复验 |

## 5. 审查阶段

`intent.review_phase` 冻结到计划并在校验时与输入快照对账；阶段变更须重建计划及结果绑定。
日常设计显式填 `design_iteration`；未填写时工具按冻结语义校验。

| 值 | 本阶段目标 | 证据不足项处理 |
|---|---|---|
| `design_iteration` | 完成当前能做的设计、计算和修正 | 未接受的阻断 FAIL、潜在 P0、REVIEW_INCOMPLETE、开放需求澄清进入本轮；其他缺口按依赖安排在本轮或冻结前 |
| `schematic_freeze` | 用户明确要求冻结 | 执行全部严重度、覆盖、绑定、资料和 HANDOFF 闸门；校验加 `--require-release` |
| `prototype_verification` | 接收实物/布局证据，追踪整改 | 只审原理图与外部证据交接，不签署整机、EMC、寿命或生产准出 |

`review-gate.json` 中的工具字段：`valid/errors` 表示记录是否可对账；`workflow.status/current_work_items`
（由开放项派生，见下）给出本轮先做什么；`release` 是原理图冻结的 GO / CONDITIONAL_GO / NO_GO。
`release` 在非冻结阶段也会计算，但**不是本轮总判定**：非冻结阶段的报告展示实际用途下的电气结论、
必要疑点及集成约束，不因未接受移交或未给完整制造资料就把整个设计标为失败。冻结 NO_GO 也不妨碍继续设计和补证。

### 待办由开放项派生

待办（`work_items`）不手写。`validate_review.py` 从 `functions[]` 的每个开放项（`open[]`，REQUIREMENT 除外）和
失败项（`fails[]`）各派生一件，写进 `review-gate.json` 的 `workflow.work_items`，编号 `W-<key>`（key 已是 W- 开头则原样）：

| 待办字段 | 来自 |
|---|---|
| `title` / `root_cause` | 开放项的 `title`（无则 `what`）/ `what` |
| `reason` | `why`，无则 `severity.consequence` |
| `next_action` | DESIGN_VALUE：“由 {owner} 确定：{spec}”；VENDOR_DATUM：`acquisition`；DELIVERABLE_PENDING：“由 {owner} 交付：{deliverable}”；失败项：“按发现项 {finding_id} 的改法处理” |
| `due_stage` / `design_option` | 开放项同名字段（`due_stage` 默认 `design_iteration`） |
| `check_ids` | 用 `open_ref`/`fail_ref` 指向这一项的行（即 `decides` 命中的方面×状态） |
| 等级 | 开放项的 `severity.level`；失败项取发现项 |

- 共享的只是补证或修改动作，不是电气结论；每条行仍保留自己的判据和证据。一件待办只有一个开放项，
  所以不再有“一行被几件待办分缺口”的归属字段；两个功能缺同一份资料时各写各的开放项（key 不同），报告按文字合并显示。
- 关联 DESIGN_VALUE / VENDOR_DATUM 开放项的待办须有 `design_option`（写在开放项上）：
  能改图消除缺口时写 `PROPOSED` 的电路改进建议及其规避的问题，不能时写 `NONE` 和原因。
  字段见 [证据不足项的电路改进建议](report-and-remediation.md#证据不足项的电路改进建议)；`--require-actionable` 时强制校验。
  改法不得以缺口的不利结果为前提（“改为更高分断方案”先假定了保险不够）；缺口能靠查标准条款或手册关闭的，
  `preference` 写 `EVIDENCE_FIRST`，先查再决定改不改。
- 一个开放项只开一条危险路径：P0 开放项的 `severity.hazard_path` 唯一；同一功能里后果等级不同的缺口分开写开放项，
  `decides` 各自限定方面与状态，P1 的方面不并进 P0 的开放项。
- 只有文字相似、同一器件或同一本手册不构成同一开放项。根因相同的 FAIL 行引用同一个失败项，改法在发现项里。
- 能按物理对象/判据拆开时优先拆开放项，而不是让一个开放项铺满整块电路。`decides` 的每条影响条目写 `via`（缺的量进到哪条条件或哪个计算输入）
  和 `rationale`；一个缺口挡几个方面不限数，超过 3 个只出 WIDE_GAP 提示。
- 阻断表示冻结影响，`due_stage` 表示工作安排，二者不能互相替代。已确认阻断 FAIL 和潜在 P0 不可推迟。
- REVIEW_INCOMPLETE 必须在本轮处理；不论潜在等级均阻断 release，不能用风险接受、下游移交或后移 due_stage 绕过。
  只剩 SR 工具自身限制、审查时已对照网表和原厂资料核对完的，不记 REVIEW_INCOMPLETE，按核对结论判定并写 `manual_verification`
  （见 [计划与结果台账](plan-and-results.md)），工具限制列入 `sr_improvements`，不进设计者待办；缺输入的缺口（手册要求、intent 声明、证据）
  不是工具限制，补齐后重生成计划。

### 纯下游验证项

**纯实物/下游判据在原理图审查中记阶段 NA（本阶段不判），并保留必需 HANDOFF。**
这是检查的阶段归属，不是产品需求不适用，也不代表试验通过。样机温升、整机能效、EMC、结构耐久、
PCB 实际间距等结果不能在原理图阶段取得；不能因此增加原理图 INSUFFICIENT 或要求 ASG 增加电路。

**判定顺序**（每条检查按序执行，不跳步；第 1 步命中即结束）：

1. 本产品是否需要这条？不需要 → 普通 NA（`NOT_APPLICABLE` + 依据）。
2. 判据里有没有原理图能判的部分：连接、额定、负载边界、保护配置、损耗预算、必要设计裕量、
   保守参数下的吸收/钳位计算？有 → 拆成独立检查，按 PASS / FAIL / INSUFFICIENT 判，不随测试项移交。
3. 剩余部分问一句：**拿到这个数，审查者今天能否在原理图上重判这一条？**
   能（数来自手册、需求、系统设计、配置表或计算）→ 先按[判“证据不足”之前先定界](evidence-proportionality.md#判证据不足之前先定界)走完五步，仍判不了才在功能判定里记开放项（kind 见[复核每条证据不足](evidence-proportionality.md#复核每条证据不足)），行 INSUFFICIENT 由它派生；
   不能（数只能由样机、PCB、结构或试验产生）→ 阶段 NA + HANDOFF。

实际负载未知、保护门限/故障输出配置未知，都是第 3 步的“能”，记 INSUFFICIENT，不是下游验证。
**固件与配置**按同一顺序拆：硬件能力按手册允许的配置范围判（允许范围内每个设置都满足 → 通过；有满足的设置 → 通过，
所需设置在条件上标 `setting{ref, group, value}` 并写进配置行；没有满足的设置 → 没通过），配置未知不挡硬件行。
配置表（PDO/PPS 能力、NTC 切档阈值、OVP 编码、GPIO 角色、恢复策略）是交付物，由逐配置组的 CFG-D01 行核，
缺它或它自相矛盾记 INSUFFICIENT（DELIVERABLE_PENDING，`deliverable_kind: CONFIGURATION_TABLE`），只挡 CFG-D01 行和需求行；
订货代码决定的工厂选项是器件身份，在 DEV-D01 核；引脚、上拉、GPIO 冲突、编程口与功能脚复用在原理图上判；
烧录镜像、读回 hash、编程模式/夹具、量产校准结果只能在生产/固件环节产生，记阶段 NA + HANDOFF（接收方“固件/生产”），
不阻塞原理图冻结（`FIRMWARE_IMAGE_RECORDED_AS_DESIGN_GAP` 提示）。
复合 REQ-D01、功能电路汇总或 PRO-C01 不能整行改 NA；设计要求照常判，纯测试要求另立检查并关联。
需求行（计划按 `intent.requirements` 生成的 `REQ-D01.<需求 ID>`）整行写 `OUTSIDE_SCHEMATIC_STAGE` 会被校验拒绝：
“工作温度 −10..50 °C”里器件温度等级是设计要求，闭壳温升才是试验，各写各的条款。
生成计划的自动判据不得删改来绕过这一拆分。

阶段 NA 行的固定写法（校验强制）：

1. `review_result: NA`、`na_reason: OUTSIDE_SCHEMATIC_STAGE`；
   `applicability` **保持 `APPLICABLE`**（产品需求仍适用），不写 applicability_evidence；
   不填 open_ref、blocking。
2. `handoff.required: true`、`scope: downstream_verification`、`product_requirement_status: PENDING_VERIFICATION`，
   写清接收角色、约束、验证方法。
3. `handoff.schematic_prerequisites` 列第 2 步拆出的检查 ID；确无前提填 `[]` 并给 `no_schematic_prerequisites_reason`。
   前提项按它自己的结果和等级处理（FAIL/INSUFFICIENT 由前提行自身阻断或不阻断），测试行不重复阻断、不升级。
4. 由 HANDOFF 跟踪，**不建 work_item**，随原理图作为清单交出，不卡冻结；不伪造 ACCEPTED。
   NA 行不因接收而变 PASS；实测结果由下游报告另行证明。

| 情况 | 原理图审查处置 |
|---|---|
| 只能靠样机取得的能效、EMC、闭壳热、寿命/环境、协议一致性及结构试验结果 | 纯测试行阶段 NA + HANDOFF，产品验收仍待完成 |
| 实际漏感/PCB 寄生尖峰，已有适用的保守参数和吸收/钳位设计依据 | 设计子判据单独判定，实际波形测试阶段 NA；保守界限不足或算不过不能移交消失 |
| 实际负载不明、保护配置未知、保证边界足以改变选型结论 | INSUFFICIENT + 具体缺口（gaps）；已证实违反则 FAIL |
| 固件配置表缺失或自相矛盾 | CFG-D01 行 INSUFFICIENT（DELIVERABLE_PENDING / CONFIGURATION_TABLE），硬件行按允许的配置范围照常判；FIRMWARE_CAPABILITY 只用于“固件能不能实现某个行为” |
| 环路增益、相位裕量这类只有样机能给的结论 | 阶段 NA + HANDOFF，补偿参数进 CFG-D01 的环路补偿组；“靠实测”不能作通过的依据 |
| 定制磁件图纸、固件/OTP 应用能否实现所需控制策略的确认等另一阶段欠的交付物 | INSUFFICIENT（DELIVERABLE_PENDING）：写欠什么、谁欠、本判定按什么假定算；不记 EXTERNAL_DATA，不向芯片厂家索取 |
| 烧录镜像、读回、编程夹具、量产校准 | 原理图前提单独判；镜像本身阶段 NA + HANDOFF 给固件/生产 |
| 资料已读、只剩计算或建模 | 本轮算完（REVIEW_INCOMPLETE）或交 ASG 的设计任务，不记 EXTERNAL_DATA（`CALCULATION_RECORDED_AS_DATA_GAP`） |
| 同一方法套在几个对象上（三只光耦的 CTR、几只电解的寿命） | 一件待办、多个位号，不拆成三件（`DUPLICATE_WORK_ITEMS`） |
| 成本、体积、效率等明确的优化目标 | 必须要求满足后列 IMPROVEMENT 或 P3，不制造未知项；它的需求行（成本目标、尺寸重量尽量小、取舍优先级、不申请某认证这类优化目标或范围说明）记 `NOT_APPLICABLE` 并在 `applicability_evidence` 引需求原文——没有判据就没有“通过”，也不是下游试验，不写 PASS、不记阶段 NA |
| 需求同时含设计与“通过某测试” | 设计要求照常判；测试要求条款写 `result: NA`、`na_reason: OUTSIDE_SCHEMATIC_STAGE` 并链接阶段 NA 检查 |

`gap_cause` 由开放项的 `kind` 推出，审查员不写；纯下游项只能走阶段 NA。
统计中阶段 NA 单列为 `NA_OUTSIDE_STAGE`，不计入普通 NA；含阶段 NA 条款的需求行列在
`stage_scope.requirements_pending_downstream`，报告在“交给后续环节的要求”末尾列为要等样机或测试结果才能最终确认，不得写成“不适用”。
`quality_screening` 的分出下游工作提示只辅助判断；工具映射失败不是产品不适用，不用阶段 NA 隐藏覆盖缺口。

## 6. 准出

- **不准出**：P0 未修；未接受的阻断 FAIL/INSUFFICIENT；适用项未执行；版本/完整性关键缺口；
  必需 HANDOFF 未形成可执行约束（接收方/约束/验证方法缺失）；开放的阻断需求澄清。
- **有条件准出**：所有检查已形成有效结论；无 P0；剩余阻断级 P1/P2 或未知项已由有权责任方按本版
  记录明确接受，约束和责任人已落实。报告保留 FAIL/INSUFFICIENT，不改写为 PASS。
- **准出**：无开放阻断项；覆盖完整、证据充分，必需 HANDOFF 已写成可执行清单（是否已被接收不影响准出）。

关闭状态：`FIXED_VERIFIED` 须给新版证据和复验标准；`ACCEPTED` 须批准人、日期、版本/配置范围、
理由与记录；`RETRACTED` 须反证与更正说明。Agent 不得自行填写批准人或替人接受。
未关闭的关键前提只能不准出，不能以“有条件准出，待后续关闭”提前放行。

允许的用语：原理图准出，可进入 PCB Layout；原理图有条件准出；原理图不准出。
禁止的用语：整板可以投板；SI/PI、EMC、热、DFM 已通过（除非另有对应审查证据并作外部引用）。

保证阈值与浮空风险的概念参考 [TI CMOS 输入说明 SCBA004E](https://www.ti.com/lit/an/scba004e/scba004e.pdf)。
P0–P3 是本审查的分级方法，不是原厂规定；具体门限查正在审查的器件。

### 假设参与定级的边界

数值推断进入严重度之前，按[假设与上界的证据门槛](evidence-proportionality.md#假设上界与实际故障的证据门槛)核来源及可达状态。
没有依据的探索值超限、不同开关阶段的极值相加、或将待实现尖峰预算当实测上界，均不能独立支撑P0/P1或FAIL。
撤回这些论据后，按仍存在的具体必需功能/保护协调缺口或有证据的危险路径重判；未证明越限不等于已证明安全。
