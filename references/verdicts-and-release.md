# 结论、分级、阶段与准出

本页统一回答：每项检查给什么结果、缺陷定几级、本轮做什么、原理图能否冻结。
准出对象是**原理图设计数据**：通过表示“原理图可以冻结并进入 PCB Layout”，不表示 PCB
已通过审查，也不表示整板可以投板生产。适用性和证据尺度见 [最小充分证据](evidence-proportionality.md)。

## 1. 四种检查结果

| 状态 | 含义 | 对准出的影响 |
|---|---|---|
| PASS | 原理图与资料/需求证据充分且符合 | 无 |
| FAIL | 原理图证据已证明存在问题 | 按 P0–P3 处置 |
| INSUFFICIENT | 本项适用，但缺会改变本判据的具体输入，无法定判 | 阻断级项未补齐或未书面接受时阻断 |
| NA | 经适用性判断确认不适用 | 无；必须写明不适用依据 |

- NA 不得代替 INSUFFICIENT；未执行项不能填 PASS，也不能用 NA 消失。
- 已有资料尚未读算的事项记“审查待完成”（REVIEW_INCOMPLETE），不得称为外部资料缺失。
- 不满足通用模板本身不构成电气缺陷。

**自动产物到最终结果**：Lint 命中不等于 FAIL，零命中也不等于 PASS；最终状态由审查者
（方式 T/C/D/V/Q）在证据链上复核后给出。

| 自动扫描/证据计算的中间产物 | 最终结果 |
|---|---|
| FINDING | 复核确认后为 FAIL；有反证排除后为 PASS，保留排除依据 |
| CANDIDATE | 判据未补齐前为 INSUFFICIENT；补齐后转 PASS 或 FAIL |
| 自动验证 PASS | 仅该对象和判据的候选通过；审查者核实模型/覆盖后才能写最终 PASS |
| SKIPPED / pending | 适用但缺输入为 INSUFFICIENT；有依据确认不适用才是 NA |
| 依赖布局、实测、结构或生产落实的要求 | 独立 HANDOFF，不替换本项结果 |

## 2. 严重度 P0–P3

先分开回答四个问题：事实是什么（连接、贴装、参数）？违反哪条适用判据？在什么工况下
影响什么功能？每个主张的证据是否充分？不能把“事实很确定”直接传给未验证的灾难后果，
也不能因后果不确定而撤掉已确认的规格不满足。

| 等级 | 判据 | 典型情况 | 准出处置 |
|---|---|---|---|
| P0 致命 | 危险应力/损坏风险、关键安全保护缺失、必需启动或核心链路确定断开 | 高压与普通外设直连；唯一供电路径确定不贴 | 必须修复并复验；不能通过接受放行 |
| P1 严重 | 必需功能/性能或推荐工作保证不满足、强制接口条件违反 | 全角不能保证启动 strap；端口少于需求 | 修复，或有权责任方明确接受后有条件准出 |
| P2 一般 | 局部非关键功能、裕量、维护测试或数据一致性问题 | 非关键故障指示不可用；误导性字段 | 处置/记录；违反项目必需验收条件时仍阻断 |
| P3 建议 | 已符合要求后的可选优化、低影响图纸卫生 | NC 属性残留、名称改进 | 择期处理 |

- 表内是定级起点，不按器件或规则自动赋级。需求关键性、发生条件、外部暴露、独立硬件保护写入定级理由；
  不凭“低概率”降级绝限风险，不编造概率/RPN。必需功能/性能偏离通常至少 P1。
- **保证范围即判据**：VIL(max)/VIH(min) 是保证范围。必须读 0 的节点最坏电压超过 VIL(max)，
  已足以确认“不能保证低电平”，通常 FAIL/P1，无需等到实物必然读错。典型翻转点、单板调通或
  室温一次测试不能证明全温/批次保证。
- 实测与分析冲突时复核版本、BOM、测点、时序、仪器和模型；可撤回“必然失效”的过强表述，
  未满足保证的事实仍保留。“must/shall”确定约束性质，但不单独决定 P0；“recommended”纳入
  受控需求或影响正常工作时按影响定级。
- 一个根因关联多个检查时按唯一 finding 统计，不把 20 个 FAIL 算作 20 个缺陷。
  已满足要求的可选优化用 `kind=IMPROVEMENT`，不能写 FAIL。

## 3. 证据置信度 A/B/C

- **A**：结论能由已验证输入直接重现（网表集合、官方限值与可复算区间等）。
- **B**：有可定位依据和适用条件的工程推导，推导链公开。
- **C**：关键身份、拓扑、要求或工况缺失；对应 INSUFFICIENT。PASS/FAIL 不得以 C 为依据。

证据来源（netlist / schematic / BOM / datasheet / requirement / calculation / test）另记，A/B 不是来源类型。
例：确认一颗电阻标 DNP 为 A；装配 BOM 与图面冲突时，“实物必定不贴”是 C——可分别记录
“装配数据冲突”的 FAIL 和“因此会断电”的 INSUFFICIENT（潜在 P0）。

待核项填 `potential_severity`，按实际需求、失效路径及工况说明，不整批定为 P1。
需求未定（REQUIREMENT_OPEN）的检查不填等级，改由 [需求澄清项](requirement-clarifications.md) 记录决策时点和冻结影响。

## 4. HANDOFF 与集成约束

HANDOFF 不是检查结果，而是原理图审查形成的下游动作。每项检查先给四种结果之一，再独立记录：

- `required`：是否需要移交；`state`：`OPEN` / `ACCEPTED` / `VERIFIED`；
- `receivers`：PCB Layout、SI、EMC/Test、结构、系统集成方/模块使用者等明确接收方；
- `constraint`：由原理图证据导出的可执行约束；`verification`：下游如何关闭。

同一项可以是“连通性 PASS + PCB 阻抗约束 HANDOFF OPEN”，也可以是“拓扑 FAIL + 修复后仍需布局 HANDOFF”。
ACCEPTED 表示接收约束，VERIFIED 才表示下游验证完成；冻结只要求必需 HANDOFF 已 ACCEPTED。

**集成约束**（模块本体范围内导出、须由外部主机/负载/系统满足的条件）也用 HANDOFF 记录，
接收方为系统集成方或模块使用者：需求指定了须接收约束的集成方时 `required: true`，按常规阻断准出；
开放模块没有指定集成方时 `required: false`，仍填 receivers/constraint/verification，在报告“集成约束”
类别列出，不计缺陷、补证任务或移交数。

### 边界矩阵

| 域 | 原理图内直接判定 | 形成 HANDOFF | 本 skill 不判定 |
|---|---|---|---|
| 电源 | 拓扑、轨压、EN/PG、反灌、时序逻辑、器件额定值 | 大电流网、去耦位置、散热要求 | PCB 压降、PDN、实测温升 |
| 高速接口 | TX/RX、P/N、电平/共模兼容、端接和耦合拓扑 | 阻抗、等长、间距、过孔与回流 | 眼图、串扰、板级 SI 仿真 |
| EMC/ESD | 防护器件选型、方向、连接和泄放拓扑 | 摆放顺序、靠近连接器、屏蔽接地 | 辐射/传导结果与认证 |
| 测试 | 调试接口和必要观测节点的电气连接 | TP 类型、禁分叉网、邻近地 | ICT 可达性、夹具与覆盖率 |
| 安规 | 隔离器件、耐压等级、跨域连接 | 高压分区与间距要求 | 实际爬电/电气间隙 |
| 器件 | MPN、符号、引脚（手册引脚定义的编号或名称）、封装字段和外围参数 | 特殊封装/摆放；焊盘编号与封装映射 | 焊盘、钢网、装配工艺 |
| 可靠性 | 可由原理图和规格确定的电压/电流/功耗应力 | 热敏器件和验证条件 | FMEA、鉴定、寿命试验 |

来自 PCB、SI/PI、EMC、热和生产活动的**原理图整改输入**仍回到本 skill 做网表复验。

### 热相关审查边界

原理图审查只检查热相关的电气前提，并向 PCB/结构提供散热约束；不把“电气选型合理”和
“实际温升合格”合成一个 PASS/FAIL。

| 阶段 | 检查与输出 | 判定边界 |
|---|---|---|
| 原理图 | 声明负载/占空比/故障状态下的损耗与额定值、温度等级和参数保证条件、适用 SOA、温度检测/保护连接与门限 | 用适用证据判电气符合性；真实电气前提缺失为 INSUFFICIENT，已证实违反为 FAIL |
| 约束移交 | 位号、工况、损耗上界或负载谱、允许结温/壳温及依据、SOA 起始温度限制 | 写入独立 HANDOFF；温度约束是下游设计输入，不是实测保证 |
| PCB/结构/样机 | 铜皮、热过孔、散热器、风道、实际结温与温升验证 | 下游完成；原理图报告只引用可追溯的外部结果 |

- 环境温度、壳温和结温分别记录，不互换。手册热阻和温升电流带有测试板与安装条件，不能当本板实测值。
- 不为下游热验证另造“必须热测试才能 PASS”的原理图检查，不因缺 PCB/结构模型或热测试给已完成的
  电气检查追加缺口，也不能仅因“还未测温”要求换件或判不准出。
- 温度条件确实影响电气判据时，先按允许范围定界并形成约束；无法确定适用额定值或保证条件时，保留具体电气缺口。

| 情形 | 处理 |
|---|---|
| 已按声明工况完成 LDO 损耗与额定核对，尚无 PCB/闭壳模型 | 电气判据独立给结果；损耗和允许温度移交 |
| 不知道 LDO 最大负载 | 负载/需求缺口，原理图阶段补齐 |
| 证据已证明功耗超过适用额定，或工作轨迹违反适用 SOA | FAIL，不能用“等热测试”替代整改 |
| 只有室温 SOA，且高温影响保护判据 | 查适用降额/模型或反算允许起始温度；无法支持判据时 INSUFFICIENT |
| 外部热验证发现过温，需改拓扑、器件或保护门限 | 引用外部证据形成原理图整改输入并做电气复验 |

## 5. 审查阶段

`intent.review_phase` 冻结到计划并在校验时与输入快照对账；阶段变更须重建计划及结果绑定。
日常设计显式填 `design_iteration`；未填写时工具按冻结语义校验。

| 值 | 本阶段目标 | 待核项处理 |
|---|---|---|
| `design_iteration` | 完成当前能做的设计、计算和修正 | 未接受的阻断 FAIL、潜在 P0、REVIEW_INCOMPLETE、开放需求澄清进入本轮；其他缺口按依赖安排在本轮或冻结前 |
| `schematic_freeze` | 用户明确要求冻结 | 执行全部严重度、覆盖、绑定、资料和 HANDOFF 闸门；校验加 `--require-release` |
| `prototype_verification` | 接收实物/布局证据，追踪整改 | 只审原理图与外部证据交接，不签署整机、EMC、寿命或生产准出 |

`review-gate.json` 中的工具字段：`valid/errors` 表示记录是否可对账；`workflow.status/current_work_items`
给出本轮先做什么；`release` 是原理图冻结的 GO / CONDITIONAL_GO / NO_GO。
`release` 在非冻结阶段也会计算，但**不是本轮总判定**：非冻结阶段的报告展示实际用途下的电气结论、
必要疑点及集成约束，不因未接受移交或未给完整制造资料就把整个设计标为失败。冻结 NO_GO 也不妨碍继续设计和补证。

### 共同根因归并为任务

结果使用 `workflow_version: 1` 和 `work_items`；每个电气 FAIL/其他 INSUFFICIENT 至少关联一个任务，
需求澄清直接生成任务，不在 work_items 重复登记；没有未决项时填空数组。

```json
{
  "workflow_version": 1,
  "work_items": [{
    "id": "W-MAG-001",
    "title": "取得磁件的受控规格",
    "root_cause": "当前资料包没有目标变压器的绕组及绝缘规格",
    "check_ids": ["<实际检查ID1>", "<实际检查ID2>"],
    "due_stage": "schematic_freeze",
    "reason": "缺口影响匝比及绝缘判断，冻结前须闭合；其他独立连接检查可继续",
    "next_action": "取得对应设计版本的磁件规格，再分别完成所关联的计算与条款核对",
    "evidence": [{"source": "input-manifest.json", "locator": "磁件规格缺失记录"}]
  }]
}
```

- 字段全部必填。共享的只是补证或修改动作，不是电气结论；各项仍保留自己的判据、严重度理由和证据。
- 关联了 `gap_cause` 为 EXTERNAL_DATA 或 DESIGN_OPEN 的待核项时，任务还须带 `design_option`：
  能改图消除缺口时写 `PROPOSED` 的电路改进建议及其规避的问题，不能时写 `NONE` 和原因。
  字段见 [待核项的电路改进建议](report-and-remediation.md#三待核项的电路改进建议)；`--require-actionable` 时强制校验。
- 只有文字相似、同一器件或同一本手册不构成共同根因。根因相同的 FAIL 共用一个任务，引用 finding 的改法。
- `blocking` 表示冻结影响，`due_stage` 表示工作安排，二者不能互相替代。已确认阻断 FAIL 和潜在 P0 不可推迟。
- REVIEW_INCOMPLETE 必须在本轮处理；不论潜在等级均阻断 release，不能用风险接受、下游移交或后移 due_stage 绕过。

### 纯下游验证项

先把判据拆清：原理图连接/额定值单独判定，实测温升、EMC、PCB 间距独立移交。不能把原理图就能
判定的欠压、绝限、保护或配置未知称为“等样机验证”。确实只缺下游验证的已计划检查保持 INSUFFICIENT，
以下条件**全部**成立时不额外阻断冻结：

1. 计划和结果的 `handoff.required` 都为 true，全部关联任务在 `prototype_verification` 关闭；
2. `handoff.scope` 为 `downstream_verification`，写明接收方、定量约束和验证方法；
3. HANDOFF 已 ACCEPTED/VERIFIED，有真实接收记录；Agent 不得代替接收方确认；
4. `handoff.schematic_prerequisites` 列出覆盖本项全部原理图前提的其他检查，且当前均 PASS；
5. 本项不是 FAIL，potential_severity 不是 P0；
6. `gap_cause` 为 DOWNSTREAM_VERIFICATION。

这不是风险接受，只是已完成原理图前提后的阶段归属。

## 6. 准出

- **不准出**：P0 未修；未接受的阻断 FAIL/INSUFFICIENT；适用项未执行；版本/完整性关键缺口；
  必需 HANDOFF 未形成可执行约束或未被接收；开放的阻断需求澄清。
- **有条件准出**：所有检查已形成有效结论；无 P0；剩余阻断级 P1/P2 或未知项已由有权责任方按本版
  记录明确接受，约束和责任人已落实。报告保留 FAIL/INSUFFICIENT，不改写为 PASS。
- **准出**：无开放阻断项；覆盖完整、证据充分，必需 HANDOFF 已被接收。

关闭状态：`FIXED_VERIFIED` 须给新版证据和复验标准；`ACCEPTED` 须批准人、日期、版本/配置范围、
理由与记录；`RETRACTED` 须反证与更正说明。Agent 不得自行填写批准人或替人接受。
未关闭的关键前提只能不准出，不能以“有条件准出，待后续关闭”提前放行。

允许的用语：原理图准出，可进入 PCB Layout；原理图有条件准出；原理图不准出。
禁止的用语：整板可以投板；SI/PI、EMC、热、DFM 已通过（除非另有对应审查证据并作外部引用）。

保证阈值与浮空风险的概念参考 [TI CMOS 输入说明 SCBA004E](https://www.ti.com/lit/an/scba004e/scba004e.pdf)。
P0–P3 是本审查的分级方法，不是原厂规定；具体门限查正在审查的器件。
