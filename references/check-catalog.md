# 检查规则总表

> 读者：审查员（规则登记在 scripts/catalog.py，改规则的维护者也读）。

本文是审查规则的唯一编号表。下半部分表格由 [`scripts/catalog.py`](../scripts/catalog.py) 生成；
改规则只改 `catalog.py`，再运行 `python3 scripts/catalog.py --write-doc references/check-catalog.md`，
测试会拒绝两者不一致。规则目的与适用边界先对照 [审查要点](review-charter.md)。

## 编号怎么读

- 规则编号为 `内容域-方式序号`。例如 `PWR-E01`：`PWR` 是电源，`E` 是保证值核对，`01` 是该组序号。
  内容域回答“查什么”，方式回答“怎么查”。在用编号不改；新规则接在所在组最大序号之后，组内序号可能有空缺。
- 计划项 ID 为 `规则编号[.实例键].锚点`，例如 `RST-T02.U3.SYS-RST-N`。审查员要补的检查登记在 `intent.rule_gaps`，
  计划工具写成 `REVIEWER_ADDED` 检查项，ID 为 `规则编号.GAP-<缺口编号>.锚点`，如 `PWR-T05.GAP-Q7-REVERSE.Q7`。每个计划项带 `rule`、`method`、`domain`，合并计划和校验结果时逐项核对。
- 格式版本（`schema_version`）：intent 4、计划 7、结果 6、电路候选 2；版本不符的文件按当前总表重新生成。
- 内容域和方式只是编号的拼法，不是审查的顺序：审查流程（五个步骤）和审查员沿着走的功能树见 [SKILL.md 架构](../SKILL.md#架构)，
  步骤间文件和脚本归属见 [架构说明](architecture.md)。

## 方式要点

- **A 自动扫描**：只报疑点（FINDING）、候选（CANDIDATE）和提示（INFO），不是结论；零命中不等于通过。
  见 [自动检查](automation.md)。
- **E 保证值核对**：只使用带出处的保证值，缺任一项即 INSUFFICIENT；PASS 写明未判定的部分。
  见 [器件资料与证据计算](datasheets.md)。
- **T 连接追踪**：逐跳记录物理脚→网络→已贴器件→网络→物理脚，同时核返回路径与参考地；
  按装配状态和工况分别追。连通只证明导电路径。
- **C 工程计算**：先确认模型，再代入实际拓扑、公差、输入/温度/负载角点；公式见 [WCA 公式](wca-formulas.md)。
  改参数时连带复算相关规则。
- **D 条款核对**：逐条对照准确型号的官方条款、errata、平台规范与需求，保留“文档章节→规则编号”阅读记录；
  平台条款实例化时记录文档/版本/页码、适用器件与模式、预期连接或窗口、实际位号/物理脚/网络与结果。
- **V 图面目检**：极性、pin1/视图、选项表、同名端、NC 标记以图形为证据；新页和变更区细读。
- **Q 覆盖审计**：功能电路汇总项（REQ-Q07）不能代替逐电路、逐工况的电路检查项；未检出也未声明的功能电路由 REQ-Q08 逐个确认。
- **H 版本比对**：旧结论不迁移，见 [改版复审](revision-review.md)。

“来源”列说明计划项由谁产生，“粒度”列说明逐什么对象展开：`Lint 内置`、`检查器·…`、`改版比对` 由脚本执行或生成；
`计划逐对象生成` 按粒度逐对象展开；`功能电路检查项` 随所属功能电路展开；`全板通用` 每块板一项。
各内容域的移交事项只形成下游约束，边界见 [结论与准出](verdicts-and-release.md#4-handoff-与集成约束)。

## 审查要点与规则归属

目的与取舍见 [审查要点](review-charter.md)。每条在用规则有一个主审查要点，跨域约束仍按判据与 HANDOFF 处理。
这是维护映射，不增加项目检查或填写字段；映射齐全不等于实际审查正确。

| 审查要点 | 要回答的问题 | 主归属规则数 |
|---|---|---|
| G1 需求与功能符合 | 要求的功能、接口和性能是否落实到电路？ | 5 |
| G2 器件与连接正确 | 实际器件、物理脚、装配与端到端连接是否正确？ | 32 |
| G3 工况下的功能与性能 | 启动、运行、掉电等适用状态下，电源、控制与信号能否按要求工作？ | 50 |
| G4 参数裕量与器件应力 | 保证值、公差及工作范围是否满足指标和器件能力？ | 23 |
| G5 保护与异常响应 | 需求内的故障、防护及隔离是否有效，动作与恢复是否合理？ | 22 |
| G6 实施、测试与下游约束 | 原理图是否可落实和验证，必要布局、热及测试约束是否明确移交？ | 4 |
| G7 证据覆盖、改进建议与复验闭环 | 是否查全且结论有据，不通过项是否明确如何改进、如何复验？ | 15 |

## 每项检查的盲区、关闭条件与常见误报

“不查会漏掉什么”是检查的理由，不表示本设计已存在这些问题，也不预设 P0–P3。
关闭条件写明证据到什么程度可以结束本项，以及哪些事不归本项；复用的事实只是方向，
不自动构成项目依赖。实际对象不同的，在结果检查项只改需要改的那个字段。

## 需求类别与审查方面

每条需求分解成审查方面，计划按（需求，方面）各生成一项 REQ-D01，判据取方面模板。分解的单位是需求里的量：带参数的方面由 `requirements[].parameters` 里有没有这个参数决定，有就问，不管选了哪些类别；不带参数的方面由类别决定。一条需求一个参数都没写时，才按类别问全部方面，计划同时列出原文里没读进参数的带单位数字（`REQUIREMENT_NUMBERS_UNREAD`）。类别拿不准就多选：多出的不带参数的方面判 NA 要写依据，少选是漏查。

| 类别 | 名称 | 怎么选 | 审查方面 | 落到 |
|---|---|---|---|---|
| INPUT_RANGE | 输入电气范围 | 原文说板子从外面接什么电：输入电压、频率、瞬态、热插拔 | INPUT_STAGE_RATING 输入级器件额定覆盖、INPUT_THRESHOLDS 启动与欠压门限覆盖、CONVERTER_INPUT_RANGE 变换级工作范围覆盖 | 系统 SYS-POWER，输入相关电路 |
| OUTPUT_SPEC | 输出电气规格 | 原文给输出的电压、电流、功率、精度或纹波的数 | OUTPUT_LEVELS 各档输出可达、OUTPUT_LIMITS 电流与功率限制、OUTPUT_ACCURACY 精度与纹波 | 输出相关电路、供电接口 |
| FUNCTION | 功能与数量 | 原文要求有某个功能或接口，或给出路数、端口数、通道数（“4 路 RS-485”“2 个 USB”） | FUNCTION_PRESENT 功能与接口存在且数量达标 | 落实该功能的电路、接口 |
| PROTOCOL | 协议与接口功能 | 原文点名协议、角色（主/从、Host/Device、PD 角色）、识别或对外引脚定义 | PROTOCOL_ROLE 协议角色与能力、PORT_DETECTION 端口识别通路、EXTERNAL_PINOUT 对外引脚定义 | 接口、主控电路 |
| TIMING | 时序与启动 | 原文说上电/掉电顺序、启动时间、复位、保持时间、看门狗 | POWER_SEQUENCE 上电与掉电顺序、STARTUP_TIMING 启动、复位与保持时间 | 系统 SYS-SEQUENCE、启动与复位电路 |
| PROTECTION | 保护与故障响应 | 原文说过流、过压、短路、反接、浪涌、ESD 等故障要怎样检测、在哪动作、动作后怎样 | FAULT_DETECTION 检测通路存在、FAULT_THRESHOLD 动作门限、FAULT_RESPONSE 动作后状态与恢复 | 保护电路、监控 SYS-MONITOR |
| MEASUREMENT | 测量与监测 | 原文要求测量或监测某个量（温度、电流、电压）并给范围或精度 | MEASUREMENT_CHAIN 检测链完整、MEASUREMENT_ACCURACY 测量精度 | 模拟与检测电路 |
| ENVIRONMENT | 环境条件 | 原文给工作或储存温度、湿度、海拔、气候条件 | TEMPERATURE_GRADE 器件温度等级覆盖、TEMPERATURE_DERATING 按温度降额、TEMPERATURE_DRIFT 敏感参数温漂、ALTITUDE_HUMIDITY 海拔与湿度影响额定 | 全板器件应力，各电路 |
| SAFETY_ISOLATION | 安规与隔离 | 原文说隔离、绝缘电压、安规类别、爬电与电气间隙 | ISOLATION_PARTS 跨隔离器件资格、ISOLATION_PATHS 隔离路径唯一、DOWNSTREAM_HANDOFF 原理图外部分移交 | 隔离接口、链路 |

| POWER_BUDGET | 功耗与效率 | 原文给待机功耗、静态电流或效率的数 | STANDBY_POWER 待机与静态功耗上界、EFFICIENCY 效率 | 电源树、变换器电路 |
| INDICATION | 指示与人机 | 原文要求指示灯、蜂鸣器、按键等人机部件及其状态 | INDICATOR_PRESENT 指示功能存在、INDICATOR_SUPPLY 指示供电独立 | 相关电路 |
