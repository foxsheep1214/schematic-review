# 适用性与最小充分证据

> 读者：审查员。

本页用于制定计划、复核自动候选和提出补证任务。规则总表是检查入口；实际判据由电路用途、
器件条款、受控需求和当前阶段决定。保留稳定编号及覆盖记录，不把一份通用模板的全部子条件
强加给每个器件、工况或功能电路。

## 先回答三个问题

1. **是否适用？** 核实实际功能、拓扑、引脚复用、装配及状态。网名、引脚候选功能、位号前缀
   只能提示；明确声明或追踪证据才能确认。排除时引用具体事实，结果 NA；用途未确定则保留证据不足。
2. **这条判据需要什么？** 把连接存在、参数选择、边界计算和实物效果拆开。T 的连通判据不要求
   C 的完整应力模型；容量证据不足不推翻已证实的接法；后续温升未测不推翻已查清的绝限。
3. **现有资料能否回答？** 先用当前网表、官方资料、受控采购规格和已有计算完成判断。仅在
   一个具体缺口会改变结论时索取补证；文档已经在项目内但尚未读、算或录入，列审查待完成。

功能电路展开后逐项判断适用性。汇总项引用检查项结果，不再次索取整套资料；统计唯一设计缺口
及任务，逐项台账数量只是覆盖规模。名称候选不展开成一组已确认适用的计算。
批量录入必须来自逐项判断，不能把某功能组的一段理由套到不同判据。共享计算可引用同一记录，
但每项须说明与本对象、额定值、工况的关系。已有资料未读算是 REVIEW_INCOMPLETE，
不冒充 EXTERNAL_DATA 或下游验证；此类未完成项在本轮关闭，放行始终阻断。

## 将判据绑定受控范围与可达状态

形成结果或补证任务前，逐条在现有证据记录中写清：来源要求及版本/定位、明确排除和条件、
本轮已承诺的验收窗口、已经证明的局部范围、实际仍未知的参数。按此确定适用性，再定缺口、
潜在后果及关闭阶段；不能从通用模板或源文件的 OPEN 标签倒推本轮还承诺了哪些保证。

- 只承诺指定温度/手册负载下的名义或时序目标时，按该场景先完成读算；未承诺的全温、任意
  网络通信、整板认证不自行设为冻结前置。未覆盖范围如实保留并写入集成约束或移交。
  这不关闭同一场景的本体额定、稳定性、安全及适用原厂无条件条款；局部 PASS 不能称全板保证。
- 潜在等级使用需求内工况，或实际供电、信号及故障路径可达且未被有效受控约定排除的工况。
  若不利情形违反明确接口条件，先核约定适用对象、装配、默认态及过渡态，核它如何在实际
  系统中实现或由受控集成方落实。条件只写在纸上、与独立供电/上拉路径矛盾，或靠尚未知的
  时序才能满足时，不能当作已有排除证据；保留该实现/可达性缺口及有依据的条件性后果。
  若实现证据有效排除该情形，把违规使用的后果写成集成约束/误用风险，不把它当受控工况中
  已有暴露或无证默认最坏已发生。确有安全相关误接待决时当场问用户（[需求澄清](requirement-clarifications.md)）。
- 排除一个高电平情形不等于排除整个 OFF 状态。低电平上界、上/掉电跟踪、钳位和返回路径
  分别核实际范围；静态电平不证明动态过程。实际可达的绝限暴露、未闭合本体条款仍逐项保留，
  不因名义 scope 限定而改 NA，也不凭“未实测损坏”降低已有违规。
- 自动准备度与工程结论分开。WAITING_EVIDENCE 不是自动 FAIL；监控链先核本任务哪些门限/
  状态是必需、IC 内置 UVLO 等能否完成它们，再对外部链给限定结论。缺必需检测/控制前提
  仍保留；没有外部监控要求不能单凭未贴独立监控报缺陷。审查者结果保存实际追踪与条款证据，
  不篡改自动候选或将一次台账填写偏差归为算法错误。

## 按实际用途选模型

| 候选规则/对象 | 适用判断与应查内容 |
|---|---|
| SDA/SCL 或多功能 GPIO | 确认本设计启用的模式及对端。只用于测试/编程时检查该接口的电平和接法；不强加运行 I²C 的地址、上拉或上升时间。用途未知不能直接 NA。 |
| DP/DM、差分命名 | 先查实际模式。充电识别脚按其检测/驱动条件查；真正高速数据链路才查共模、差分摆幅、端接和交流耦合。 |
| FB/ADJ | 先核传递关系。电阻分压、光耦电流反馈、内部设定和数字设定采用各自模型；FB 名称不证明存在分压 Vref。 |
| 分立晶体管 | MOS 开关的 RDS(on) 保证条件仅用于需要该导通电阻的工况。线性调整/源极跟随器查工作点、输出范围、VGS 绝限、损耗和适用 SOA；BJT 查基极驱动、VBE/VCE 与额定值。 |
| 电感/绕组 | 继电器等切换感性负载查关断续流。共模滤波器查额定/绝缘/滤波；变换器磁件查能量传递、复位和尖峰处理，不强制套一颗独立续流二极管。 |
| 输入保护 | 被动保险丝/MOV/NTC/桥堆查浪涌与保护协调；存在主动门限、MOS 或监测链才查对应 UVLO/OVLO、SOA、反接或检测使能。 |
| power_in 供电脚 | 先确认 VCC、HV 启动/检测、VBUS 等实际角色与原厂要求。电气类型不等于每脚必须有本地去耦；输出储能电容也不等同 IC 去耦。 |
| LDO 纹波、噪声与 PSRR | 逐状态追踪该输出实际供电的负载及耦合路径；板上存在 RF 器件不证明每路 LDO 都供应敏感负载。仅在原厂条款、受控需求或有据的负载敏感度适用时索取相应噪声目标；路径未知保留具体待核。该噪声子判据不适用不豁免输出范围、稳定性、额定和热损耗。 |
| 复位、启动、救援 | 外部 RESET、strap 或可编程平台存在且有相应要求时查其时序/恢复；电源 IC 的 UVLO、软启动和重试按实际条款查，不强加 SoC 的 RC 复位或 Maskrom。 |
| 关断、短路、保护状态 | 核规定的安全状态、应力、动作及恢复条件。允许停止调节时不再要求正常输出精度、纹波和闭环相位裕量。 |
| “缺少某项保护” | 先查路径上各 IC 自带的保护：PD 控制器的自适应 VO OVP 与阻断管、电源控制器的 FAULT/VCC OVP、过流计时等，按其门限和动作延时判断。门限由寄存器设定时归固件任务，不按“缺独立保护”报证据不足。 |
| 连续可调输出、多路供电取大 | PPS/AVS、宽输入等按整个连续范围扫描，重点算两路供电交接点附近的应力和线性损耗；只核两个端点不能判 PASS。 |
| 从参考设计派生的电路 | 列出全部偏离：拓扑或绕组抽头改接、器件额定降低、控制器替换（引脚耐压与内置功能不同时，照搬的外围防护可能不再够用）。每条按本设计条件复核；“与参考相同”只作线索。 |
| 厂商合格配对（接口时序） | 主控厂商的设计指南/硬件手册明确指定外接器件型号、接法与时钟配置（如 RP2040 指定 W25Q 系列 QSPI Flash），本设计型号、接法一致且未提高时钟时，SIG-C09 按厂商合格配对判 PASS（B），引用该指南页；运行时钟上限等配置写成固件约束移交。主控手册不给接口时序本身不构成证据不足。仅是社区/第三方参考，或换型号、改接法、提高时钟时，仍按两端保证值计算。 |
| 不属原理图判定的需求 | 生产测试策略、知识交付、候选比较、尺寸优化等，判 NA 并写明范围，或作为移交；不记证据不足。 |
| 两端子或标准定义的连接器 | L/N 插脚、USB Type-C 插座等的脚义由标准规定，按标准核对即可，不另要结构化脚表。 |
| 对插件极性固定的连接器 | 对插的是行业标准或商用成品插头（XT30/XT60、DC 圆插、USB 等），壳体决定极性时，须按原厂图纸或标准核“符号脚号 ↔ 焊盘 ↔ 壳体极性标识”；需求里按图面标签记录的对端约定不能代替这一核对，取不到图纸记 INSUFFICIENT（EXTERNAL_DATA）。对端由本项目自定义线束时，按图面标签约定核对即可。 |

一个排除理由只覆盖相应规则及状态，不能借此删除真实的保护、绝限、隔离或核心功能检查。

### 噪声路径资格

PWR-C14 的噪声子判据判 NA 前，按状态记录每个已识别敏感物理电源脚已资格化的完整上游供电、
可能耦合及返回路径和出处，以及本输出已核全部负载范围与适用噪声目标。跨磁珠、0Ω、开关、稳压器等
边界继续追踪；按 fitted 状态使用 NetGraph，PowerTree.source_of 只给来源候选，须审查者核功能及完整性。
同网无命中、来源查询为空、状态或负载范围未闭合不能推出 NA；未知路径具体保留。存在本轨目标或敏感
耦合时仍核预算，噪声 NA 不关闭输出范围、稳定性、额定或热判据。

### 条款条件与任务约束

引用手册前先保留条件从句、目的和覆盖状态。“to ensure 某状态”的接法只证明达成该状态的条件，
不能脱离本项目是否需要该状态升为无条件缺陷；分别核默认状态、过渡过程、初始化策略和保证边界。
缺必需启动保证仍可为证据不足；实际违反适用绝限或无条件条款时继续判 FAIL。
图纸显示偏好与受控验收要求分别记录。任务要求保留完整网名、符号缓存或冻结区域时，建议先验证改法能
满足该约束；继承的全局标签不单凭显示偏好判错线，也不强制改 namespace。真实可读性或 ERC 违规另判。

## 模块本体、完整系统与制造核准

从需求与作者实际用途确定本轮承诺，再解释未知项；不要先套全系统或制造冻结模板，再要求公开项目补齐模板。
审查范围（只审本体，还是含指定对端的完整系统）以需求为准；需求未确定时当场问用户（[需求澄清](requirement-clarifications.md)），
不由审查者自行认定为本体范围，再据此判 NA。

- **开放接口模块**：本体已有的电平转换、上拉、供电、关断及反灌路径仍须读算；据此给出端点所需的灌电流、
  门限、电容/速率、掉电兼容等集成约束。未指定外部主机/负载时，未知端点不自动成为本体缺陷或本轮待补证任务；
  需求已限定为本体范围时，整链兼容判据按该范围依据判 NA，保留本体计算，集成约束按 [结论与准出](verdicts-and-release.md#4-handoff-与集成约束) 记入 handoff。若需求已经指定对端或承诺兼容某标准/组合，仍须核保证条件，
  不能借“模块”或工作演示豁免。模块自身关键器件的参数缺口同样保留。
  外部主机未指定时，总线上拉范围、总线电容、主机电压窗口、灌电流等端点兼容判据不记证据不足：本体部分（板上上拉、电平转换、供电与反灌）读算后判 PASS/FAIL，主机侧条件写成集成约束（如“主机 VOL ≤ 0.4 V 时灌电流 ≥ 3 mA，总线电容 ≤ 400 pF”）。需求只点名主机系列（如“树莓派”）而未定具体型号时，用该系列公开规格的公共部分判定，型号间差异写成集成约束。
  外部负载未指定时同理：由本体器件额定、开关限流、调节能力等导出允许的负载包络（如 Iout_max 随 Vin 的关系），
  写成集成约束，不问用户；需求或作者给出了额定负载时，按该负载审查。
- **名义功能与定量保证**：约某电压、某负载的功能主张，先核拓扑、标称设定及适用的工作证据；没有给出精度、
  温度或输入范围承诺时，不自行引入精密输出或全角点保证要求。手册某行测试条件不同，先判断是否影响当前主张，
  不是自动追加保证矩阵；涉及明确输出容限、临界绝限或保护保证时，适用的 Min/Max 仍不可省略。
  作者未承诺精度的输出轨，若给下游器件供电，下游的推荐工作范围（DEV-C05）与绝对最大额定构成隐含容限，
  仍按保证 Min/Max 核输出窗口（PWR-E01/PWR-C02），不能以“名义功能”判不适用。
  反之，需求无输出容限且板上无下游负载时，PWR-E01 实例及 PWR-C02（自动或审查者生成）的输出窗口判据没有验收窗口：以需求和网表负载
  为 `applicability_evidence` 判 NA，在 rationale 记录名义设定计算，并把输出窗口写成集成约束；不因 Vref Min/Max
  未取得而保持证据不足。约束中的窗口用手头已有资料计算（资料已在手须读入）；不在手时写成公式及待代入的保证参数，
  由集成方按需取值，不因此建证据不足任务。“约 5V”等名义主张只用名义设定与工作证据核对，不据此自定允许偏差。
  NA 只覆盖输出窗口：PWR-C02 的调节能力（如 Boost 在 Vin_min、Iout_max 下的最大占空比与开关电流，Vin 接近或
  高于 Vout 时能否维持调节）及 PWR-C03 等非窗口判据仍按实际工作状态判定；同一 PWR-C02 实例兼含两类判据时，
  拆为窗口与调节能力两个实例分别记录。
- **物料身份与制造绑定**：保留符号/物理功能脚、极性及实际应力检查。普通指示灯、无源件或标准连接器缺完整
  采购料号，不自动阻断功能审查；按受控最小规格或有据边界（见 [通用件最弱档基准](commodity-floors.md)）判断，制造料号/焊盘绑定按实际复刻或冻结任务处理。
  若身份或参数未知会改变电气结论（如磁件饱和、补偿所需有效容量、临界钳位或安全等级），仍列具体的证据不足项。
- **正常拓扑行为**：停开关但输出仍有直流通路、没有独立保护等，先记录实际行为及使用约束；只有它违反需求
  内的关断、安全或故障响应要求时才判 FAIL。不得为此补造“输出必须归零”或固定保护级数要求。

功能证据只支持所覆盖的版本和工况，不能将上述范围裁定改写成全板/全工况 PASS。每条撤回的证据不足项注明不适用
主张及替代的本体检查/集成约束；真实疑点保留最小补证，不以减少台账数量为目标。

## 无源转接板的审查边界

先按作者用途与实际器件判定是在审转接板本体，还是含主机、线缆和负载的完整接口系统。
本体逐针核对信号、电源与返回路径、方向、装配和对端定义；连通正确不等于整条总线的电平、
灌电流、上升时间或掉电注入已合格。官方工作示例只支持其实际版本与组合，不能当全工况保证。

连接器的 POWER 类型是引脚传递电源的标记，不自动产生 IC 去耦要求。核实为无源连接器后，
可用现有 `intent.decoupling.components.<ref> = {"kind": "other", "citation": "已核对的器件与用途出处"}`
排除该去耦候选；保留顶层输入指纹与装配声明，重新生成计划。不得仅因 J/P 位号、板上没有电容
或希望减少证据不足项就排除，真实用电脚、未知器件和厂家要求的输入滤波仍独立审查。

已在 `intent.devices` 保存完整脚表的连接器，可另在 `intent.device_kinds` 声明原厂类型及原文页码，
经 datasheet audit 核验为 VERIFIED 后，默认 IC 去耦候选不再展开；原始脚表、身份、防护和接口检查仍保留。
依据及电源/返回脚写入去耦清单的 `non_decoupling_connectors`，未核验或仅靠符号/位号不能走此路径。
显式声明的端口输入电容条款和去耦 group 优先，仍逐状态展开；额定检查的补证目标是已贴电容，
连接器料号/针序及端口浪涌限制分别审查，不能移用为电容耐压、ESR 或有效容量证据。

无源转接板未承诺提供上拉、电平转换、复位或稳压时，不能因本板没有这些元件判缺陷。
把外部必要条件写成明确的集成约束：供电与逻辑域、上拉所在侧、允许的总线电容/速率、
电源针负载和未上电端口行为。按本体范围作出的不适用判断需引用范围依据；
实际要求审整个系统时，未知外部电路仍须补证，不能借“转接板”豁免。涉及本体额定载流、
器件身份等未证实主张仍保留具体缺口；不得把通用连接器手册直接当实际 BOM 的额定保证。

带检测接点的插座还要核内部接点：先用物理脚表识别检测端与壳地端的分组，再按插入/拔出等
实际状态逐一展开内部连通。两个外露检测端可能内部同组，不能因另一端未接就判断回路断开，
也不能把同组的另一检测端当地端硬接地。网络名、符号别名与物理脚编号分开记录；
内部连通只适用于已绑定的器件变体，不改写原网表，也不移用到独立双端开关。

## 证据够用的边界

- 参数取值回看原件的准确型号行、单位与数量级、合并单元格和脚注，记录可定位依据；
  文本提取可能错列或丢位时核原始图面。不能借同系列另一型号的参数，或把限值移用于表中未覆盖的工况。
- 原厂表头或注释已保证所需温度/电压/负载范围的 Min/Max，直接用于该范围；无需逐温度点
  另找证据。推荐工作温度证明允许工作，特定参数仍遵守其注明的条件。环境温度与实际结温分开。
- 正式边界比较使用适用的保证值。典型曲线可支持早期估算及有依据的 B 级工程推导，明确假设、
  裕量和后续验证；不能冒充 Min/Max 或证明临界绝限/保护保证。参数无全角保证时先看是否真正
  影响本判据，再确定需要的局部边界或验证，不自动索取全器件、全状态保证矩阵。
- 普通无源件可用受控最小规格（阻值、公差、耐压、温度等级等）完成相应选择检查；不统一要求
  每颗都有完整 MPN 手册。确有 DC bias、ESR、纹波电流、绝缘或寿命依赖的器件须有相应数据。
  安全关键器件仍明确其额定值、类别及必要认证要求，最终整机认证移交后续阶段。
- 官方脚表、同型号参数和共同采购规格只维护一份。相同事实引用原记录并核适用条件，不反复
  抄整篇手册；一个来源可靠且适用即可，不为补证数量要求重复来源。
- 最终烧录包、批量固件哈希和生产签署可在后续阶段提供；决定硬件正确性的协议能力、引脚
  复用、输出/保护参数、反馈及补偿配置在冻结前明确，不能整体推给固件或样机。
- “尽量小”“最好十年”等偏好先列目标和评估假设，不因缺硬阈值判 P1；成为明确必需验收条件
  后才按该条件判定。不得把模板示例数值当项目限值。

## 判“证据不足”之前先定界

记一条证据不足之前，按顺序走完这 5 步；任何一步能下结论就停在那一步。计划把这 5 步原文放进每个功能框架
（`functions[].checklist`），审查员在功能判定里照着走，不必通读本文；框架外自建的功能同样适用。
器件参数的工作点和手册测试条件对不上时，第 1、4 步按[工作点定界表](bounding-table.md)走：表里有的器件类别和参数，
推法、顺序、公式和推不出时记哪一档都由表定，门禁按表核对（2026-10-23，用户：“必须按表”）；表的出处和说明在 [WCA：器件参数定界口径](wca-formulas.md#器件参数定界口径)。

1. **先用手册里已有的界限。** 把手册中与这个功能有关的条款都列出来：工作条件下限（如启动恒流源的最低电压）、
   使能/欠压门限、相邻测试点的保证值（单调时夹出上界）、温度系数的 min/max、限流门限与频率钳位。表头的测试条件
   只是测试条件，不是使用范围。必需功能和性能类判据（含 P1）可用“保证值 + 有依据的余量”判 PASS（B），并把样机实测记为必需移交。
2. **算出了余量就下结论。** 记录里已有“X > Y”“X < 额定”这样的比较，余量够就判 PASS（B），写明所用假设；
   余量不够就判 FAIL 或风险并给出改法。不能一边算出余量，一边保留证据不足。余量怎么判见[余量判定规则](margin-verdicts.md)；
   余量写进功能判定的 `calculation.margin`（多个方面各写一条），`basis` 写它证明什么：保证最坏值满足即 PASS，确会出现的工况或完整最坏范围不满足
   即要求失败项（F4），估算不决定，见 [余量的依据](results-format.md#功能判定functions)；
   设计值挂成开放项而功能已有计算时必须写出该方面的余量（F8）。审查员自己假设的参数（倍数、系数、预算）算出的余量
   不是最坏情况，先按第 4 步取手册允许的最坏值再比。
3. **本设计自己要定的量不向厂家要。** 变压器漏感、辅助绕组调整率、补偿码、配置值由设计决定：反算允许范围，
   写成设计规格交给 ASG，或移交样机实测（见 [WCA 故障时间轴](wca-formulas.md#故障停能与器件耐受的同一时间轴)“未约束的参数反算范围”）。只有器件本身的、厂家才知道的参数才向厂家索取。
4. **没有保证值就按公开资料界限判断。** 损坏、过热、保护类判据缺本工况的保证值时，按[定界表的推法](bounding-table.md#推法)和先后
   找公开资料界限并记在 `worst_case.bound`（阈值电压的测试电流低于工作电流时它只是下界，不能当上界）。
   保证类推法的界限下仍满足就 PASS(B)（估算推法过关是“合格但有风险”，见[余量判定规则](margin-verdicts.md)），把界写进 `conditions`；不满足就判 FAIL 并给改法，不挂起等厂家回复。厂家不会为一颗通用件出具
   本机工况的承认窗口，“向 X 取得 Y 的保证”不是取得路径。
5. **只有走完 1–4 仍判不了**，才记证据不足，并在缺口里写明查过手册哪几条、为什么都不够。公开资料界限一条都没有时，
   `worst_case.curves_checked` 列出为找界翻过的曲线、特性表和应用笔记。

器件参数怎么定界（齐纳低电流、MOS 实际 VGS、二极管漏电、单调外推、只有典型值、典型应用等效、脉冲、检流、物理上限）见
[WCA：器件参数定界口径](wca-formulas.md#器件参数定界口径)；定出的界怎么判见[余量判定规则](margin-verdicts.md)。下面两类只说适用范围：

- **额定字段缺失的通用件**：BOM 只给阻值/容值、封装或系列时，按 [通用件最弱档基准](commodity-floors.md) 定界、判定和定级
  （50% 判定表、MLCC 可订购档、计划预判检查项的封闭理由码、DEV-D04 约束表与 [BOM 约束怎么定级](commodity-floors.md#bom-约束怎么定级)都以该文件为准），不需要具体料号，
  缺额定字段只在 DEV-D04 记一条，不在每颗器件上重复记证据不足。
- **隔离器件与安规**：需求没有声明安全隔离、认证或安规等级时，光耦、隔离器按功能隔离审查（CTR、传输、上拉、
  供电），绝缘耐压与爬电/电气间隙记 NA，并写成集成约束“本板不承担安全隔离”。需求声明了安全隔离时不放松：
  按需求的安规标准逐项核对；认证证书（UL/VDE/CQC）列明的系列额定可作为额定依据。

PDF 文本提取可能把 µ 显示成 m（如“30 ms”实为 30 µs）。决定结论的时间、电流数值要对照渲染页核单位。
文本层把 kΩ 印成 kW 且全文没有 µ 的资料，审计记 `unit_glyphs: SYMBOL_FALLBACK`；引它的 ms、mA、mH、W 条款在 ④ 出 `UNIT_GLYPH_SUSPECT`，核过后在 `says` 写明。

## 身份冲突与身份分支

PART/VALUE 冲突，或图面/BOM 与链接资料互相矛盾时，建立身份分支，可按候选继续分析，但不得认定候选为实际物料：

- 记录不一致本身判 DEV-D04 FAIL（数据缺陷，按影响定级）；
- 依赖实际物料参数的电气判据保持 INSUFFICIENT，逐分支给条件结论（如“若实为 Y5V 则有效容量不满足”），
  补证为确定实际料号；
- 候选只取设计数据明写的身份：实例 PART/MPN、BOM 料号、Datasheet 链接所指的具体型号、Value＋封装尺寸。
  不得拼接字段合成候选（如用链接的系列名配 Value 推出另一个具体料号），不得引入设计数据之外的同系列料号；
  封装库名只给尺寸，不是系列身份。
- 只有 Value＋封装尺寸的分支不是具体物料，按 [commodity-floors.md](commodity-floors.md) 对应类别（功率电感、MLCC 等）判：
  同尺寸有引用目录的可订购档满足时该分支 PASS（B）并带最低规格约束；没有可引用目录时该分支不合格（甲：BOM 该写明的规格没写，改法写所需最低规格）。
- 汇总：全部候选分支都违反判据时，才可判该电气判据 FAIL；全部候选分支都满足判据时，判 PASS（B），
  结论写明“实际物料在上述候选内即成立”，并把候选范围写入 BOM 约束；其余一律不合格（甲），
  发现项的改法写定下实际料号及所需最低规格。

身份没有冲突、只是档位或后缀未定（如光耦 CTR 分档、温度等级后缀、通用 NPN/肖特基、同系列不同代）时，按系列中对本判据最不利的档位（CTR 最低档、温度范围最窄档、手册中最差的保证值）计算：最差档仍满足，就判 PASS（B），不再要求确定具体后缀；最差档不满足，才把“须选某档以上”作为证据不足或修改任务。差异只影响固件配置（如 I²C 地址后缀、上电默认寄存器）时，不记证据不足：电气检查按各后缀分别成立判定，把“固件配置须与实装后缀一致”写成集成约束。

一个可信原厂文档可确认器件类别；库名和商城转引同一 PDF 不算两个独立证据。

实例 MPN/Value、BOM/采购字段、Datasheet 和官方订货信息证明实际物料；libsource、缓存 primitive 与库 ID
说明符号来源，不能仅因来源名称旧而自动认定采购型号冲突。复用符号须按实际 MPN 核完整物理脚、脚义、
封装字段与适用参数，记录兼容映射；不兼容仍判对应身份/引脚缺陷。实际实例采购字段与 Value/公差/额定
组合冲突保持 DEV-D04 FAIL，并按身份分支复核电气；来源名兼容不消除这些实际冲突。

## 保证值核对的例外

保证值核对（方式 E）在资料未 AVAILABLE 或缺保证值时判资料不足，判据见 [保证值核对](datasheets.md#二保证值核对方式-e)。两个例外：

- **边界已证明违反**：已有保证值或可信边界已证明违反判据，且缺失参数取任何允许值都不能改变结论时，该 E 检查项与
  同一判据的审查者检查同判 FAIL；证据写明所用边界及结论不依赖缺失参数的理由，同一根因共用一个 finding；补齐资料后
  复核数值，不降回证据不足。
- **没有验收窗口的名义输出**：需求无输出容限且板上无下游负载时，PWR-E01 及 PWR-C02 的输出窗口判据判 NA，
  做法见上文[名义功能与定量保证](#模块本体完整系统与制造核准)；调节能力等非窗口判据照常审查。

## 原定资料取不到时

按本条判据**逐参数补证与替代**，不把“缺整本 datasheet”等同于“所有判断都无法进行”。
先确定需要证明的参数、工况与验收窗口，再选择能关闭缺口的路径；不必穷尽所有路径。

1. **换渠道取同一型号**：查原厂、授权分销商、LCSC/立创及存档/镜像，核完整后缀、封装、
   档位与版本。访问被拒或超时就换渠道，记录失败原因；镜像文档也须核实原厂出处和身份。
2. **取同型号的其他原厂证据**：应用笔记、评估板指南、勘误、技术支持答复可证明其中明确
   覆盖的参数或接法；核文档适用型号、工况和版本。示例电路或典型值不能自动升级为保证值。
3. **取供应商受控规格**：采购规格、承认书或定制件图纸可用于其明确保证的项目，尤其是
   磁性件和无源器件；记录供应商、料号/版本、适用批次或采购约束，不用未确认报价参数代替。
4. **从电路反算要求，再取最小补证**：先算允许的参数区间，例如指定栅压/结温下的最大
   RDS(on)、所需耐压或漏电流上限，再补能证明目标器件落入区间的证据。反算结果是选型
   要求，不是器件实有参数；缺口只写会改变结论的参数、工况和取得方法。
5. **按参数借用相似器件资料**：用于建立候选模型、探索参数范围和敏感度，逐项说明
   器件结构、功能、驱动/偏置、温度及测试条件的可比性。多个相似型号的数值包络仍只是
   探索范围，不能直接当作原器件保证范围；同封装、同额定电压或同系列名称本身不证明等效。
6. **实测与模型校准**：用目标器件的测量约束关键参数，记录样本/批次、工况、测量误差及
   覆盖范围。校准后的仿真用于已建模行为；样本结果、典型模型不能证明未覆盖的全温/全批次，
   未建模的保护、热行为或失效机理仍需独立证据。尚未实测时列验证任务，不写成已证实。
7. **建议换成有资料的器件或改电路**：列满足反算要求的替代件及引脚、封装、驱动、额定值和动态行为
   差异，或让现有器件回到保证条件内的电路改法，给出 BOM/原理图修改与复验条件，写进任务的
   `design_option`。只有设计实际修改并复验后，才能用新证据关闭对应项；建议本身不改变当前结论。
   器件被用在原厂测试条件之外（如齐纳低于测试电流、光耦低于测试 IF）时，原厂通常不会补发保证，
   这类缺口优先推荐改设计（`preference: DESIGN_FIRST`），不要只写“向原厂索取”。

借用资料时，在已有计算记录中逐参数标明“本器件已确认 / 相似器件参考 / 分析假设”，
附来源页码、适用工况、采用区间、不利方向及敏感度结果，由 checks.evidence/rationale 引用。
不新增必填 schema。相似性推断的置信度不高于 B，但 B 标签本身不足以支持 PASS/FAIL：
只有目标器件的适用范围有依据，且不确定性不会改变本条结论，或该判据已证明不依赖未知参数，
才按前节规则下结论。否则只给条件计算，受影响主张保留 INSUFFICIENT/C，并列最小补证。
不能用相似器件证明原器件身份、安规认证、绝对最大额定值或未获证实的保证参数。
同型号原厂证据与受控规格按其实际覆盖范围定置信度，不因缺整本手册一律降为 B。

资料覆盖审计如实保留 NOT_FOUND；替代资料不能把本物料改成 AVAILABLE，也不能冒充本器件保证值写进 E 检查项。
E 检查项仍缺保证值时判资料不足；审查者计算可支持其有证据的具体主张，须关联原检查并说明覆盖差异，
不能借新增审查者项删掉原检查、隐藏缺口或绕过冻结闸门。

## 复核每条“证据不足”

沿用四态检查结果；需求没说清的不在这里：当场问用户，答复写进需求清单（[需求澄清](requirement-clarifications.md)）。
下表为检查尚不能判断的原因，不是独立问题数量：

| 原因 | 开放项 `kind`（检查项的 `gap_cause` 由它推出） | 处理 |
|---|---|---|
| 真实资料缺口 | VENDOR_DATUM（→ EXTERNAL_DATA） | 指出缺哪一参数/身份/工况、影响哪一判断，列最小取得方法和关闭阶段。`checked` 列查过的条款 id、`why_insufficient` 写为什么都不够，`acquisition` 写向谁取得，`worst_case` 写公开资料界限下的最坏情况：`bound{condition, value, basis}`、`result` 和带 `basis` 的 `margin`：保证最坏值下证明满足就已判定，开放项撤掉；证明不满足走 F4；按典型斜率外推的是 ESTIMATE，可保留开放；没有任何公开资料界限时写 `not_boundable_reason` 加 `curves_checked`（翻过的曲线、特性表、应用笔记）和 `operating_point_specified`：手册根本没规定器件在本工作点怎么工作（例如某输出只在电源高于某值时给出、本机低于它），是设计依赖未规定工作区的风险，记失败项（`outside_specified`）并给出回到规定区的改法，不是缺资料。手册的情况按四档判（2026-10-23 定）：给了这个量的限值而工作点超出，按余量判没通过；厂家参考电路或应用笔记有同样接法且本板负载不重于参考电路，可判通过（条件写 `reference_circuit`）；写了这种用法但没给这个数，是缺厂家数据（`operating_point_specified: true` 加 `specified_by`；`specified_by` 不能是没覆盖工作点的那条测试点限值，要引写了这种用法的条款、应用说明，或 `regime` 覆盖工作点的典型曲线；引典型曲线（条件写 `curve: true`；应用说明的文字不是曲线，不写，也不要求估算）时另写 `worst_case.typical_estimate`，即按曲线读出的估算余量，估算已经不够就记失败项，余量按典型曲线记 REACHABLE_CASE，2026-10-23 定）；这种用法没写或超出额定，判没通过（`outside_specified`，查过的范围含推荐工作条件或电气特性节，引脚工作点另含引脚说明节）。脚上电压超绝对最大而手册没给注入电流、超 SOA 曲线、超额定电压而没给浪涌额定，同样是超出规定区，不是缺资料（定界表这几格兜底为 OUTSIDE_SPECIFIED，2026-10-26 定）。标准规定的量（预期短路电流、污染等级、海拔修正系数）按标准条款取值，手册首页的额定和分断类别直接读取，公开数据页抓取失败属 REVIEW_INCOMPLETE，这三类都不是缺资料。“已读 X 第 N 页，再按 … 复算”也不是缺资料：资料在手只差计算的，本轮算完或交 ASG。光耦寿命末期 CTR 由寿命检查项 DEV-C06 算出所需的保留比例并写成选型约束；电解电容寿命按厂家寿命公式或 10 °C 加倍规则估算（DEV-C02 寿命检查项）；MOS 热态 RDS 按同一测试点的保证值乘归一化曲线的比例估算。这些都不向厂家索取“保证”，SR 也不自编衰减系数。 |
| 设计尚未决定 | 不设（2026-10-26 定，见[结果格式](results-format.md)） | 先反推这个值要满足的界，再看归谁定（另一环节欠的交付物——定制件图纸、固件能力——同样按乙写成约束，没有单一数值的写成条款）。甲：原理图或 BOM 本该写明（器件值、额定、耐压、料号写成 TBD 或没写）——记失败项，改法写反推出的值；乙：归另一份设计文件（磁件规格、固件配置、PCB）——写 DESIGN_CONSTRAINT 条件，余量按约束的不利端算，满足判 PASS，并把约束移交给定它的一方。可编程器件的配置表不审（手册声明的能力判为可达）。设计里已有的值（电阻阻值、已选器件、已写的热目标）照常按最坏情况判 PASS/FAIL。AI 先完成可做的选型/计算，到真实取舍点再请人决策。 |
| 审查尚未完成 | REVIEW_INCOMPLETE（同名） | 明示还未执行的阅读、计算或录入并继续做，不说成外部资料不存在。临时台账可记证据不足，不能据此宣称审查完成。工具限制但审查者已核对完的，改按审查者结论判定并写 `manual_verification`，不用本原因。 |
| 纯下游验证 | 不设（不是 INSUFFICIENT） | 按 [判定顺序](verdicts-and-release.md#纯下游验证项) 拆出原理图前提单独判；只能由样机/PCB/结构/试验产生的结果记阶段 NA + HANDOFF，产品要求仍待验证。 |
| 用户明确暂缓 | 不设（不是 INSUFFICIENT） | 是审查范围的说明，不是结论：检查项记 NA + `na_reason: USER_DEFERRED` 并引用户原话，暂缓的需求不生成检查项；报告列在“本次不审的范围”，不挡定稿（2026-10-27，用户：A）。 |
| 检查口径过严 | 不设 | 现有资料已够判定，或不属原理图判定范围：改判 PASS/NA 或改为移交，不保留证据不足。 |
| 不适用/重复汇总 | 不设 | 有依据则 NA；汇总引用具体成员缺口，不生成重复补证任务。 |

一个缺口影响多项检查时，逐项判断这一项的结论会不会因缺口而改变：不会改变的（如缺的是额定值，而本项只核连接与极性）照常判 PASS/FAIL，只在结论真正取决于缺口的检查上记证据不足，并在报告中按缺口归并，不按检查条数放大。

报告里资料不足只剩缺资料一种。审查没做完不进报告：有 REVIEW_INCOMPLETE 时不出报告；用户暂缓的列在“本次不审的范围”。

每个保留的开放项在 `what` 写具体缺什么，例如“缺输入浪涌电流及持续时间，无法比较保险丝与桥堆 I²t”；
不要写“缺完整手册/全部应力证据”或只写“待确认/待实测”。

VENDOR_DATUM 写 `checked`（查过的条款 id）、
`why_insufficient`、`acquisition`、`worst_case`（公开资料界限与余量，或 `curves_checked`）和 `closure`。其他 kind 不写这些：
REVIEW_INCOMPLETE 本轮自己做完。字段全表见
[功能判定](results-format.md#功能判定functions)。

设计没定的乙写成条件，不开项（甲是失败项）：

```json
{"id": "c6", "kind": "DESIGN_CONSTRAINT", "source": "evidence/engineering.md", "locator": "claim BIAS-VCCMIN",
 "says": "T1 辅助绕组 5 V 空载最低峰值 ≥ 13.5 V", "limit": {"min": 13.5, "unit": "V"},
 "regime": "5 V 空载、−10..105 °C", "owner": "磁件设计", "handoff": 0, "use": "辅助绕组最低峰值取约束下限"}
```

- 功能的 `calculation` 和 `conditions` 写哪个判断因缺口不能成立；已有事实与未知边界分开，不泛称“影响安全”。
- `scope`：所需数值范围、单位、模式、版本、对象、工况或状态；只索取能改变该判据的条件，
  不默认扩大到全温全工况。既有受控负载包络已足够时，不再要求每个用户的实际负载实测。
- `acquisition`：取得路径和承担角色；先查已有文件/计算（`checked`），只有真实缺项再找厂家或需求责任方。
- `closure`：拿到材料后复核什么、达到什么条件才关闭；只是“收到资料”不等于通过。
- `decides`：这个缺口让哪些方面（规则标题）在哪些状态判不了；其余检查项照常 PASS。

例：负载未知时，索取该电源轨在启动、稳态和故障重试时的最大电流及脉宽/占空比，
由系统设计给受控负载包络或从现有负载手册计算；重算电流能力、压降、应力及适用 SOA 后给结论。
保护配置未知时不开缺口：手册允许的配置范围里有满足的设置就判通过，所需设置标 `setting`，交给配置表编写方。

两个功能缺同一份资料时各写各的开放项；关闭阶段写在开放项的 `due_stage`。
工程已有资料能回答的继续读算，不能靠填表把 REVIEW_INCOMPLETE 包装成外部缺口。

“移交后续设计”明确写 PCB、结构、固件或样机阶段，所需输入、设计约束和关闭方法。
例如：硬件给最大损耗/允许结温；结构确定散热路径和高温降额；样机核实温升。
热判据按 [热相关审查边界](verdicts-and-release.md#热相关审查边界) 拆分：缺负载、适用额定值或
温度保证条件可能影响电气判断；缺板上热阻、热仿真或温升实测本身不构成原理图电气缺口。
日常设计不等待接收签署才继续；实际移交与冻结依照 [verdicts-and-release.md](verdicts-and-release.md) 的独立闸门，
OPEN 在正文写“待后续团队处理”，不得暗示已被接收或已经验证。

## 能否用电路修改消除缺口

把 INSUFFICIENT 归为 EXTERNAL_DATA 之前，再问一次：改原理图能不能让这条判据
只依赖已有的保证值？常见的情形：

- 器件工作点落在手册保证条件之外：改偏置、换有对应条件保证的器件，或换不依赖该参数的拓扑；
- 余量只差一点：换压降/漏电更小的器件、调整分压或门限，让最坏值落在判据内；
- 规格只有标称类别：定下有曲线和额定值的确切料号（这本是设计动作，按甲记失败项）；常规阻容感、二极管不走这一条，
  按 [通用件最弱档基准](commodity-floors.md) 写 BOM 约束；
- 参考设计里有更简单的已验证做法：列出偏离点和改回的代价。

能改就在任务里写 `design_option`（`PROPOSED`）：按改后电路逐条说明规避了什么问题、哪些检查因此
可以闭合、还剩什么，以及新增的代价（成本、体积、损耗、热、需要改的规格）。要用到的计算按已有资料
做完；需要改已确认规格的，写成待用户决定的前提，不自行改需求。确实无法靠改图消除的（磁件供应商
承认、固件配置、只能实测的量）写 `NONE` 和原因。

## 交付前的必要性复核

最终台账与报告交付前，逐条检查未决项：规则确实适用吗？现有资料读过/算过吗？缺口确实改变本判据吗？
已在另一任务或检查项中要求了吗？应在本轮、冻结前还是后续解决？答不清时先修正计划或继续审查。
真实电气缺口仍保留；不能为压低数量改成 PASS，也不能为补齐模板扩大实际审查范围。

每条补证、澄清及移交的关闭条件反查到现有来源要求，在证据记录保留该条的要求/排除/条件、已证范围及真实未知：
全温、系统实测、认证及 BEFORE_FREEZE/BLOCKING 按上文[受控范围与可达状态](#将判据绑定受控范围与可达状态)
核本轮承诺和实际依赖；OFF 或故障的潜在 P0 核实际供能/信号路径及排除条件的实现依据；源文件 OPEN 按
[需求原文到审查要求](requirement-clarifications.md#需求原文到审查要求) 区分；自动 WAITING_EVIDENCE 不当电气 FAIL，
审查者限定 PASS 也不反推完整自动保证已经成立。格式校验不能替代这一步。

### 可调字段与固定驱动保证

先对照实际器件模式/寄存器和硬件配置列可调变量，再写补证或改图任务。模式/使能/占空比不等于电流档位；
固定恒流输出仅给典型电流时，不将典型值当保证上限，也不索取器件没有的调流寄存器。负载电流/温度判据
缺保证时，索取真实适用的上下界、受控温度/占空比包络及其证明，或建议具有保证边界的替代驱动/限流方案；
方案需说明实际拓扑中怎样改变电流和需连带复验的压差、功耗及功能，不能套用串联电阻或不存在的设置。

功率开关的栅压、损耗与 SOA，以及假设、上界与实际故障的证据门槛，见 [WCA](wca-formulas.md#功率开关实际栅压关联损耗和-soa)。
