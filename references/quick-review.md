# 快审

> 读者：审查员。

器件不多的板（默认不超过 40 个位号）、设计中途的检查用快审：一位审查员直接审，一位复核人独立复核，不走五步流水线。
定稿前的审查、器件多的板、改版复审仍走 [SKILL.md 的执行流程](../SKILL.md#执行流程)。

由来（H-001，2026-11-16）：11 个器件的电源小板走五步流水线用了 92 分钟、149 项检查，只报出两条文档类 P3；
同一份设计不带技能直接审 3 分钟，报出指示灯正向压降使低温下几乎不亮、2 m 线缆热插拔过冲没有阻尼等 6 条。
检查项清单把注意力引到了流程性条目上，所以快审把顺序倒过来：先凭工程判断审，知识框架只用来查漏。

审查纪律不变：只读原理图、网表、PDF、BOM 和需求（被审对象是 ASG 交付目录时照 [workflow-handoff.md](workflow-handoff.md)，
设计方的报告和 `record/` 不读不引用）；结论由自己取证、自己算；不改被审设计。

## 审查

1. **读输入**。器件的规格以网表里的字段为准（BOM 可能没带全规格列），判“规格缺项”前两处都看。需求（有需求基线的按基线，已定的澄清照它审、不重问）、网表、BOM、PDF 逐页看一遍。
   可以跑 `parse_kicad.py`（或 `parse_netlist.py`）加 `read_bom.py` 得到 `db.json` 方便查连接；不写 `intent.json`，不生成检查计划。
2. **凭工程判断审一遍**，先不查清单。至少走到这几处：
   - 每个有源器件对手册核引脚功能与连接、绝对最大额定、推荐工作条件和推荐外围（含必需的电容容量、类型与位置）。
   - 逐条需求算出余量：数值取手册保证值（最小/最大），算最坏组合；只有典型值的写明是估算。
   - 需求里写了的每种工况逐个过：上电、掉电、输入范围两端、空载与满载、温度两端、接反、输出短路、热插拔与线缆等。
   - 每个器件的规格够不够下单：阻值/容值与规格文字一致、额定电压/电流/功率、封装、料号或可采购的规格。
   - 对外接口逐针核对端约定，未上电、对端先上电时有没有反灌或误指示。
3. **用知识框架查漏**（框架目录见技能目录的 `.knowledge-framework`）。只查与本板实际有的电路和器件对应的条目，读过的记下来：
   - `知识/典型电路/` 里本板各功能电路对应的条目：逐条过“必算项”“必需外围”“已知坑”。
   - `知识/设计准则/降额与应力/` 的 `降额值.json` 与 `常规件最弱档.json`：按需求或澄清定的降额等级核受应力最大的几颗
     （输入侧电容与二极管的电压、功率器件的电流与结温、连接器每针电流）；应力明显很低的常规件不逐颗算。
   - `知识/失效与故障分析/`、`知识/器件类别/` 里本板用到的器件类别的常见失效方式，看有没有对应到图上的弱点。
   - 冷扫可选：`lint.py db.json` 打印的 FINDING/CANDIDATE 逐条判一下，是问题的写进发现，不是的不写。
4. **不查的**。原理图阶段的交付里 Footprint 字段留空是约定（封装库归 PCB 环节），不列为发现；规格里没有封装尺寸、买不出唯一的件才算规格缺项。
   流程和文档完备性（FMEA 范围、验证方法是否齐全、下游交接清单逐条列出、追溯矩阵）不在快审范围；
   PCB、热、EMC 的实现交给后续环节，只写原理图上能定的约束。不为凑数列与结论无关的条目。

## 报告

写 `审查报告.md`，篇幅与板子规模相称（十几个器件的板不超过约 200 行）：

- **结论**：能不能往下走，必须改的有哪几条。
- **发现**：每条写严重度（P0 可能损坏器件或危及安全；P1 必需功能可能不达标；P2 局部或次要问题；P3 可选优化）、
  位置（位号、网络、页）、问题、依据（手册页码与数值，或算式）、怎么改、怎么验证。没有把握的写“需确认”并说明缺什么。
- **逐条需求符合性**：一张表，每条需求写结论、余量或依据。
- **风险与交给后续环节的约束**：合格但余量小或靠估算的项；要 PCB、热设计、对端或样机验证接着做的事。
- **查过的知识条目**：列出读过的典型电路、降额规则等条目，各一句“用它查了什么”。
- **对 SR 的反馈**（可选）：知识框架里查不到或有错的。

审查员不写“复核记录”，也不自己复核：复核由工作流另派的复核人做。

## 复核

复核人没有参与审查，只拿同样的输入和这份报告：

1. 每条发现回到网表、BOM、PDF 和手册原文独立核一遍：位号和网络对不对、手册数值和页码对不对、算式重算一遍、
   严重度与后果相称不相称。站不住的删掉，证据不足以定性的改成“需确认”，定级偏高偏低的改。
   需求写明的工况（接反、短路、热插拔、温度两端）下有引脚超过手册绝对最大额定的，至少定 P2，可能损坏器件的定 P1 或 P0，不因“形式上超出”“多半没事”定成 P3。
   “需确认”不等于降级：后果成立时会让必需功能不达标的，仍按 P1 或 P2 写，注明要确认什么；只有确认后多半不成立的才降。
2. 按这张漏查清单扫一遍，报告没提到又确有问题的补成发现：
   每个有源器件的每个引脚都有去处且符合手册；每条需求都有结论；电源入口的接反、过压与热插拔；每个对外引脚的未上电状态；
   BOM 里值与规格互相矛盾、规格缺额定；指示灯、上下拉这类小电路在最坏角是否仍工作。
3. 直接改 `审查报告.md`，在末尾“复核记录”逐条写：保留、改了什么、删除及原因、新补。
