# 按功能电路组织审查：电路树、接口、系统级与全板检查

状态：七步全部实施（2026-10-21/22，器件归属唯一、行归属、接口识别、接口检查项、系统级、树上的覆盖与报告、拆分计划生成并拒收旧记录，见改进台账同期条目）。基线：当前工作区（电路候选步 1–7 与 Codex 合并方案 §3–§5 已在工作区，未提交）。
台架：R5 两份首审记录（Claude 与 Codex，同一网表、同一技能版本），只读，只取汇总数字，不在 SR 里留任何位号或网名。

## 0. 一页摘要

审查顺序改成工程师审图的顺序：先识别板上的功能电路，再逐块电路按规则判这类电路是否满足要求，
在电路内部用详细规则逐项审器件，然后审电路之间的接口。不属于任何一块电路的内容分两层：
**系统级**（电源树、地、监控、上电时序、主控引脚分配）和**全板与文档**（图纸、物料、网表卫生、需求追溯、覆盖）。

```text
板
├─ 系统级功能：电源树与功率预算、地与参考地分区、电源监控、上电时序与恢复、主控引脚分配
├─ 功能电路（来自电路候选与审查员的决定）
│   ├─ 电路级检查项：这类电路的规则（变换器电压裕量、保护门限、晶体负载……）
│   └─ 器件检查项：电路内每颗器件的身份、引脚、工作条件、应力、去耦……
├─ 接口（脚本从电路成员推出）
│   ├─ 电路对接口：两块电路之间的信号、控制网络
│   ├─ 链路接口：跨电路的保护链、启动链、隔离带，带自己的器件
│   ├─ 供电接口：电源轨从源电路到负载电路（归系统级电源树，接口上只查负载侧要求）
│   └─ 对外接口：连接器引脚，本板边界
└─ 全板与文档：图面、物料与库、网表卫生、需求追溯、覆盖审计、改版复审
```

规则编号、判据、检查器和校验器都保留。变的是**每一行检查归谁**：每行恰好有一个所属对象，
即某块电路、某个接口、某个系统功能或全板，报告和功能判定都按这棵树组织。

R5 台架的三个数说明为什么要这样改（第 1 节）：

- 两份记录的电路级检查行只配上了 **1 行**（Claude 99 行、Codex 150 行）。同一块电路成员相同，
  工作态的写法和网络名是否带图纸路径不同，标识就不同。电路级的行应当以“电路编号 + 工作态”标识。
- 逐器件的行有 222 行不在任何电路下，其中 **218 行**的器件其实属于某块电路，审查员审电路时看不到它们。
- 接口类的行只有 **8 / 11 行**，而按候选算，普通电路之间有 7 对接口、20 条信号网络，另有 4 条跨电路链路。
  接口审查现在基本缺位。

迁移分 7 步（第 5 节），每步一次提交、测试先行，每步用两份记录的配对率衡量。

所以成员相同也配不上。候选已经把电路编号和工作态固定下来，电路级的行应当只用这两样作标识。

### 1.3 器件行不在电路下

Claude 记录里 222 行逐器件的行没有挂在电路上，其中 218 行的器件属于某块电路。
数量最多的是器件身份、官方物理脚、推荐工作条件覆盖、引脚处置四类（各约 30 行），其次是阈值型保护窗口、栅源驱动、去耦。
审查员在功能判定里判这块电路时，这些行在另一张表里，结论可以互相矛盾，校验器也不知道它们属于哪块电路。

### 1.4 接口没有自己的位置

逻辑电平与驱动匹配、掉电与跨域注入、时序裕量、接口方向语义这几条规则，现在作为电路检查项挂在
I²C、电平转换、SPI、UART 等总线类型下面，只有板上声明了这类电路才展开。
电源板上的控制接口（使能、故障锁存、PGOOD 经光耦回传）和启动链、保护链都没有接口这一层，
使能来源、复位链这类规则按单颗器件展开，看不到另一端。

### 1.5 接口试算

用候选成员（四颗控制 IC 的角色按两份记录的声明模拟核验）推接口：

- 直接按候选算：37 条信号网络连着两块以上电路，涉及 29 对电路，很多网络同时连 4 块电路。
  原因是跨电路候选（两条启动链、一条保护链、一条隔离带）与变换器共用器件。
- 把这 4 条跨电路候选当作链路接口，它们自己的器件归链路，与普通电路共用的器件归普通电路：
  普通电路 8 块，只有 1 颗器件同时属于两块普通电路；普通电路之间 20 条信号网络、**7 对接口**。
- 另有 9 条共用电源轨（每条连 2–7 块电路）、3 个地网、约 10 条连接器网络。

所以接口识别有两个前提：器件归属唯一，以及跨电路链路单独作为接口。
用审查员手画的电路试算时，Claude 有 9 颗、Codex 有 30 颗器件同时属于几块电路，接口无法推出。

## 2. 目标与不变的部分

目标

- 每一行检查恰好有一个所属对象：电路、接口、系统功能或全板。报告、功能判定和覆盖审计都按这棵树组织。
- 每颗已贴器件恰好属于一块电路或一条链路接口，或者在未归属清单里写明不审的理由。
- 接口由脚本从电路成员和网表推出，审查员不画；每个接口有自己的判定，两端的条件都在里面。
- 结论只在叶子上判：电路的结论由它的电路级和器件检查项汇总，接口的结论由它的检查项汇总，不另设一层独立判断。
- 两份记录用同一候选文件和同样的决定时，计划逐行相同，配对率 ≥ 90 %。

不变

- 规则编号、判据、方式字母、问题模板（`catalog.py`）；只改部分规则的展开粒度和来源（附录 A）。
- 功能判定的格式与 F1–F12、条件五种、余量依据、影响条目；接口和系统功能复用同一格式。
- 检查器的清单、扫描和证据计算；它们生成的行改为挂到所属对象下。
- 电路候选与决定（`circuit_candidates.py` / `circuit_decisions.py`），只收紧器件归属。
- SR 不存项目先验：规则按器件类别、引脚名、电源域写，夹具用合成板。

## 3. 设计

### 3.1 所属对象

计划的每一行新增 `owner`：

```json
{"kind": "CIRCUIT", "id": "POWER_CONVERTER-<核心器件>"}
{"kind": "INTERFACE", "id": "IF-<电路A>~<电路B>"}
{"kind": "SYSTEM", "id": "SYS-POWER"}
{"kind": "BOARD"}
```

`owner` 由计划写，校验器重算、不信记录里的值（与检查项标识同一做法）。
报告的章节、功能判定的行列表、覆盖审计都按 `owner` 分组。

### 3.2 电路树

**器件归属唯一。** 候选生成后，每颗已贴器件有一个所属：

- 只在一个普通候选里的，归它。
- 在跨电路候选（保护链、启动链、隔离带）与一个普通候选里的，归普通候选，链路只引用它。
- 只在跨电路候选里的，归那条链路接口（3.3 节）。
- 两个普通候选同距离共享的（`shared`），由审查员的决定选一个，另一个引用；决定要引用。
- 走不到的进未归属清单，由审查员写归属决定（`add`）或不审理由，计入 REQ-Q08。

引用成员出现在电路的功能判定里，可以被条件和计算引用，但不生成行，不进覆盖计数。

**电路下的两级检查项。**

- 电路级检查项：这类电路的规则（附录 A 的“电路级”），按电路 × 工作态展开，工作态按类型固定（`catalog.CANDIDATE_STATES`），增态要引用手册模式名。
- 器件检查项：器件和引脚粒度的规则（附录 A 的“器件”），按器件所属电路挂入，逐器件或逐引脚展开，粒度不变。
  去耦、功率开关、感性负载等检查器生成的逐器件行同样挂入。

电路的功能判定只有一份，框架的 `members`（要判的行）同时包括两级：电路级检查项的方面（电压裕量、电流应力……）和
器件检查项的方面（身份、引脚处置、工作条件、应力）。器件检查项多数是事实核对，派生规则不变：
判了的方面派生行，没判的方面不默认通过。

**结论只在叶子上判。** 电路的结论 = 它全部检查项的汇总（有 FAIL 即 FAIL，否则有证据不足即 OPEN）。
不设“这类电路是否符合要求”的独立结论，避免一个说通过、一个说不通过。功能判定的 `verdict` 继续由开放项和失败项决定（现有规则）。

**检查项标识。**

| 所属 | 标识 |
|---|---|
| 电路级 | 规则、规则版本、电路编号、工作态、判据 |
| 器件 | 规则、规则版本、位号（与引脚）、工作态（若有）、判据；所属电路只作归属，不进标识 |
| 接口 | 规则、规则版本、接口编号、工作态、判据 |
| 系统与全板 | 规则、规则版本、对象（轨、页、需求编号……）、判据 |

电路级的行去掉成员表和网络表，因为电路编号已经确定成员；器件行不带电路，因为改了电路划分，器件本身的检查不变。
这改变合并方案 §5 只去掉电路名的做法：候选编号现在由脚本确定，可以进标识；成员表不能进。

### 3.3 接口识别

**定义。** 一条网络连着两个不同所属对象的器件引脚，这条网络就是这两者之间的一个接口网络。
同一对所属对象之间的接口网络合成一个接口。地网不是接口，归系统级的地与参考地分区。

**四种接口。**

| 种类 | 怎么识别 | 编号 | 挂哪些规则 |
|---|---|---|---|
| 电路对接口 | 两块普通电路之间的信号、控制网络 | `IF-<电路A>~<电路B>`，按编号排序 | SIG-T04 方向语义、SIG-C07 电平与驱动、SIG-C08 掉电与跨域注入（两端电源域不同时）、SIG-C09 时序（有时序要求时）、RST-T01/A04 使能来源、RST-T02/A06 复位链 |
| 链路接口 | 跨电路候选（保护链、启动链、隔离带），带自己的器件 | `LINK-<候选编号>` | 链路自己器件的器件检查项、PRO-D02/PRO-C03（隔离带）、链路两端的电平与注入 |
| 供电接口 | 电源轨，源电路到各负载电路 | `RAIL-<轨>` | 负载侧要求：PWR-C14 纹波与噪声预算；源侧能力归系统级电源树 |
| 对外接口 | 连接器引脚 | `EXT-<连接器位号>` | DEV-D03 对端定义、DEV-C04 载流、PRO-D03 对外防护 |

差分链路规则（SIG-T01/T03/A01/A02/E02）跟着链路两端走：一端是连接器的挂对外接口，两端都在板内的挂电路对接口。

**端点角色由脚本推。** 每个接口网络的端点写成 `{owner, pin, role, domain, supply}`：

- `role`：DRIVER / RECEIVER / BIDIRECTIONAL / PASSIVE。由引脚类型、引脚名和 powertree 的来源推导（输出、开漏、电源输出为驱动端）。
- `domain`：端点所在的参考地分区（`checkers/domains.py`）。
- `supply`：端点器件的供电轨（powertree）。

推不出角色的端点记缺口（与 DEV-D02 同一做法），接口照样生成，相关规则行判证据不足并指向缺口。

**接口判定。** 每个接口一份判定，复用功能判定的格式：`id` 为接口编号，`objects` 为端点引脚和网络，
`states` 取两端电路工作态的并集里需求涉及的那些（默认运行、两端上电先后、一端掉电）。
条件来自两端器件的手册：驱动端的 VOH/VOL 与驱动能力、接收端的 VIH/VIL 与耐压、掉电时的输入漏电与钳位。
F1–F12 照常适用。

**规模控制。** 数字板上一颗主控可能有几十个 GPIO 连到十几块电路。为避免接口数爆炸：

- 接口按所属对象对聚合，不逐网络建判定；
- 逐网络的行只在规则需要时展开：SIG-C08 只在两端电源域不同的网络上展开，SIG-C09 只在声明了时序要求的总线上展开；
  同一电源域、推挽到 CMOS 输入的网络由接口判定统一判一次。

### 3.4 系统级

系统功能每块板固定几项，计划直接生成，不经候选：

| 系统功能 | 编号 | 规则 |
|---|---|---|
| 电源树与功率预算 | SYS-POWER | PWR-T01 拓扑、PWR-C01 功率预算、PWR-A01 轨无驱动、PWR-A04 同基名多轨 |
| 地与参考地分区 | SYS-GROUND | PWR-T06 地网划分与连接 |
| 电源监控 | SYS-MONITOR | PWR-A06 未被监测的轨、PWR-T04 逐电源域监控覆盖 |
| 上电时序与恢复 | SYS-SEQUENCE | RST-T03 上电顺序与恢复 |
| 主控引脚分配 | SYS-PINMAP | SIG-D13 主控引脚复用与分配 |

系统功能也写成功能判定，`objects` 为轨、地网或主控引脚。它和电路的关系通过供电接口与控制接口表达：
电源树判“每条轨的源能力够不够”，供电接口判“负载要求的纹波与噪声是否满足”，时序判全板的先后，
电路对接口判每一处使能和复位的来源。全板工作态表（断电、启动、运行、待机、故障）仍由 REQ-Q03 审覆盖。

### 3.5 全板与文档

图面目检、图纸卫生、BOM 与库字段、网表卫生（悬空网、网名分裂、无源孤岛、NC 网、引脚类型冲突）、
资料覆盖、需求追溯与口径、覆盖审计、改版复审，直接逐行判，不包成功能（现有规则）。

覆盖审计新增两条，都是机器能数的：

- 每颗已贴器件恰好属于一块电路或一条链路，或在未归属清单里写明不审理由（REQ-Q08 扩展）。
- 每个接口都有接口判定，接口里需要展开的规则都有行（REQ-Q07 扩展到接口）。

需求追溯（REQ-D01）的要求条款链接到电路、接口或系统功能的检查项，链接目标的所属对象进报告。

### 3.6 检查器的位置

检查器继续负责清单、网表扫描和证据计算，不再是一个独立的行来源。它们生成的行按对象归位：
逐器件的行挂入器件所属电路，逐链路的行（差分、I²C）挂入对应接口或总线电路，逐轨的行挂入系统级或供电接口。
检查器的接口不变（`plan` 钩子仍返回计划项），计划在汇总时补 `owner`。

### 3.7 报告结构

报告按树的顺序写：结论与准出 → 系统级 → 各功能电路（电路级结论、器件问题）→ 接口 → 全板与文档 → 待办与移交。
每块电路一节，节内先写这块电路的问题和结论，再列器件问题。待办仍由开放项派生，标出所属对象。

### 3.8 代码组织

`plan_review.py`（约 1400 行）按树拆成几个模块，主流程只做汇总：

| 模块 | 内容 |
|---|---|
| `plan_circuits.py` | 电路级与器件检查项、电路功能框架 |
| `interfaces.py`（新） | 接口识别、端点角色、接口展开与接口框架 |
| `plan_system.py` | 系统功能与它们的行 |
| `plan_board.py` | 全板与文档、需求、覆盖 |

`catalog.py` 的展开粒度增加 `interface`（逐接口）、`interface_net`（逐接口网络）、`system`（逐系统功能），
来源增加 `interface`、`system`。规则编号不变。

## 4. 验收指标

在 R5 台架上（两份记录用同一候选文件，四颗控制 IC 角色模拟核验）：

1. **归属唯一**：已贴器件里同时属于两个所属对象的为 0；未归属的都有决定或理由。
2. **接口可复现**：两套决定下推出的接口集合相同；普通电路之间的接口数在 5–10 对（试算 7 对）。
3. **配对**：两份记录重新生成计划，电路级检查项配对率 ≥ 95 %（现在 1 / 99），总配对率 ≥ 90 %（现在 51.4 %）。
4. **不过严**：总行数增加不超过 15 %；接口判定数不超过（普通电路数 + 链路数 + 连接器数）。
   合成数字板（主控 + 两路 LDO + I²C + 调试口）上接口数不超过实际接口数 + 1。
5. **全量测试**通过，现有变异全部被杀；每步新增变异被杀。

## 6. 风险与取舍

- **器件确实被两块电路共用**（偏置供电同时给两颗控制器、一颗电阻分压同时进两个比较器）。
  归属唯一不否认共用：一块电路拥有它、生成它的行，另一块电路引用它、在条件和计算里用它。
  归属选错不影响器件行的配对，因为器件行的标识不带电路。
- **链路既像电路又像接口。** 保护链、启动链有自己的器件和计算（分压、光耦传输、锁存门限），也连着两块电路。
  本设计把它作为带自有器件的接口：自有器件的检查项挂在链路下，两端的电平与注入按接口判。
- **接口数在数字板上可能很多。** 按所属对象对聚合，逐网络的行只在规则需要时展开（3.3 节规模控制），验收 4 设上限。
- **端点角色推不出**（无源网络、模拟信号、双向总线）。记缺口，规则行判证据不足；不让审查员手画接口。
- **过严**：接口和系统功能会增加工作量。新增的行必须由具体规则和条件触发（例如两端域不同才展开注入检查），
  不为结构完整而生成空行；行数上限是机器能数的护栏。
- **检查项标识变化**：步 2 和步 4 改标识，与旧记录配不上。按现有约定不做兼容层，旧记录只读、不再发布。
- **总线是电路还是接口。** 本设计把总线（I²C、SPI、CAN……）当作电路：它有自己的上拉、端接、地址；
  每颗器件挂上总线的那一处，是这颗器件所属电路与总线电路之间的接口。

## 7. 待定的问题

- 启动链、保护链作为链路接口，还是作为普通电路？本设计选链路接口（3.3 节），理由是它们的问题多在两端的配合。
- 系统功能是否允许按板型增减（例如没有主控的电源板没有 SYS-PINMAP）？本设计按触发条件生成：没有对象就不生成。
- 器件检查项是否全部进电路的功能判定，还是事实核对类（身份、物理脚、库字段）仍逐行手填、只是挂在电路下？
  本设计倾向后者：功能判定只收需要计算和条款判断的方面，事实核对类挂在电路下逐行判，减少功能判定的篇幅。
