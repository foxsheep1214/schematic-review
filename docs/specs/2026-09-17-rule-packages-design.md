# 规则总表 V3.1：稳定编号、功能包与全板项

日期：2026-09-17。上一版设计见 [2026-09-17-check-catalog-design.md](2026-09-17-check-catalog-design.md)。

## 1. 要解决的问题

V3.0 按“内容域 × 检查方式”重排了编号，但检查条目本身仍有四类问题：

1. **重复**：同一件事分散在多条规则里，例如 NC 网络的两种判别（NET-A04/NET-A05）、保护管 SOA 与
   开关管 SOA（PWR-C07/DRV-C02）、跨电压域的三条规则（SIG-C02/SIG-C06/SIG-D05）。
2. **疏漏**：34 条“人工补查”规则不进计划，是否执行全靠审查者记得；地网划分、复位期间 IO 默认态、
   逻辑电平匹配、时序裕量、推荐工作条件、引脚处置等常见问题没有规则。
3. **不成体系**：功能覆盖（13 条 Q 规则）和电路类型（9 种）是两张表，名字不一致（RESET/STARTUP、
   USB/USB_C），功能检出后只生成一条汇总项，成员检查要等人工声明电路才出现。
4. **低效**：未检出的功能逐个生成 UNDETERMINED 项；检测点取样侧（PWR-T02）按每条电源轨生成。

同时，编号已经发布，今后调整不能再整体重排。

## 2. 稳定编号

- 编号发布后不改名、不复用。合并或删除的规则登记在 `catalog.RETIRED`，写明替代规则；
  使用废弃编号的计划项会被 `spec_errors` 拒绝，并提示替代编号。
- 新规则接在所在组（内容域 + 方式）已发布的最大序号之后。组内“在用 + 废弃”编号从 01 连续，
  测试据此检查；在用序号因此可能出现空缺。
- `scripts/tests/issued_rule_ids.txt` 记录全部已发布编号。测试要求它与“在用 + 废弃”完全一致：
  删规则而不登记废弃、加规则而不登记账本，测试都会失败。

## 3. 第一步：规则与计划结构

### 3.1 合并与废弃（26 条）

| 废弃 | 改用 | 理由 |
|---|---|---|
| NET-A05 | NET-A04 | NC 网络判别合为一条；伪网络作为提示级（INFO）输出 |
| PWR-T02 | ANA-T01 | 取样侧是检测与监测链的一环；按轨生成改为随功能包生成 |
| PWR-C07 | DRV-C02 | 保护管与开关管的 SOA 判据相同 |
| PWR-C08 | PRO-C01 | TVS/熔断器协调并入防护器件协调 |
| PWR-C12 | PWR-C06、PRO-C01 | 开关限流并入保护门限，熔断特性并入防护器件协调 |
| PWR-D04、ANA-D02 | DEV-D05 | 未用电源脚、未用运放通道统一为引脚处置 |
| SIG-C02、SIG-C06、SIG-D05 | SIG-C07、SIG-C08 | I²C 专用电平/掉电判据推广为通用的电平匹配与掉电注入 |
| DOC-V03 | DOC-V02 | 命名与图框并入图纸卫生 |
| CLK-D02 | CLK-C01 | 晶振外围电阻属于起振计算 |
| SIG-Q01～Q10、CLK-Q01、RST-Q01、PRO-Q01、REQ-Q06 | REQ-Q07 | 功能覆盖统一为功能包汇总 |

### 3.2 新增（14 条）

DOC-T01 装配选项一致性、DEV-C05 推荐工作条件覆盖、DEV-D05 引脚处置、PWR-T06 地网划分与连接、
PWR-C14 纹波与噪声预算、RST-T04 复位期间 IO 默认态、SIG-C07 逻辑电平与驱动匹配、
SIG-C08 掉电与跨域注入、SIG-C09 时序裕量、SIG-D13 主控引脚复用与分配、SIG-D14 高速串行链路、
SIG-D15 音视频接口、REQ-Q07 功能包覆盖、REQ-Q08 未检出功能确认。

判据调整：DOC-V01 增加页间连接符与层次端口；DEV-D03 的未用针处置移到 DEV-D05；
PWR-C02 的 LDO 压差交给 PWR-E02；PWR-C06 增加开关连续电流、快断与热保护；CLK-C01 增加反馈/串联电阻；
NET-A04、DOC-V02、ANA-T01、PRO-C01、DRV-C02 按合并内容改名并扩写判据。

### 3.3 来源与粒度

`Rule` 增加 `scope`（展开粒度：输入、全板、逐页、逐网络、逐引脚、逐器件、逐电源轨、逐链路、
逐电路×工况、逐功能包、逐装配配置、逐需求、改版基线）。“人工补查”来源取消，换成：

- `board`（全板通用）：每块板生成一项，对象 `{"board": "BOARD"}`；准备度按 `BOARD_MATERIALS`
  所列资料判定。
- `package`（功能包成员）：只经功能包展开。
- `plan`：计划逐对象生成。DEV-C05/DEV-D05 逐 IC/模组生成；DEV-D03/DEV-D05/PRO-D03 逐连接器生成；
  DOC-T01 本步按全板一项（第二步按装配配置展开）。

### 3.4 功能包

`catalog.PACKAGES` 合并原功能目录（检出正则、必需资料、移交约束）与电路类型，共 19 个：
POWER_CONVERTER、POWER_PROTECTION、ANALOG、STARTUP、CLOCK、I2C、SPI、UART、CAN、RS485、USB、
ETHERNET、DDR、STORAGE、RF、HSSERIAL、AV、ISOLATION、DEBUG。成员只能是审查者执行的 T/C/D/V 规则。

计划展开：

1. 网表检出、`features` 声明或 `circuits` 声明任一成立时功能包适用，生成 REQ-Q07 汇总项
   （coverage_parent，判据列出全部成员）。意图声明不适用但检出或声明了电路时为 UNDETERMINED，
   并报 `INTENT_NETLIST_CONFLICT`。
2. 适用时生成全部成员：声明了电路逐电路×工况展开，未声明时按功能包展开一次
   （对象 `{"package": 名称}`，ID 如 `SIG-D07.USB`）。I²C 已识别连接区域时由检查器逐区域展开，
   不再重复生成包级成员。成员项带 `package` 字段。
3. 未检出也未声明的功能包合为一项 REQ-Q08，逐个确认不适用；在 `features` 声明后重新生成即可消除。
4. `features` 中不属于功能包的名字视为项目自定义功能，生成 REQ-Q07 与（未检出时）REQ-A02。

### 3.5 契约变化

- 计划 `schema_version` 3：成员项用 `package` 取代 `circuit_type`；功能汇总由 REQ-Q07/REQ-Q08 表示；
  `rule_plan` 不再含 PWR-T02。
- 意图 `schema_version` 3：`circuits[].type` 与 `features` 键取功能包名；旧名 RESET、USB_C、CAN_RS485
  报错并提示新名。
- 改版影响：对象含 `board` 或 `package` 的项按全局依赖处理（GLOBAL）。
- Lint：工具伪 NC 网络输出为 NET-A04 的 INFO，CLI 单列“提示”，JSON 增加 `info_count`。
- `ReviewPlanner.generate()` 统一全部自动计划项的生成顺序，计划构建与结果校验共用。

### 3.6 验证

- 全部单元测试通过；新增稳定编号、功能包展开、全板项、逐位号项、改名拒绝与 NC 提示的测试。
- 电路评测集 166 例对照 07238d3 基线：协议与数据指纹不变，逐例记录与指标逐项一致，零回归。

## 4. 第二步：装配状态与器件脚表统一

### 4.1 共享声明

意图里随网表版本变化的声明集中到三处（`scripts/board_intent.py`）：

- `input_sha256`：覆盖电气指纹加符号声明脚、伪网与输入完整性。声明了 `assemblies`、`devices`
  或任一检查器段就必须给，过期即拒绝。原来 9 个检查器段各带一份 `db_sha256`/`input_sha256`。
- `assemblies`：1–32 个装配状态（`id`、`citation`、`population`、`jumpers`），全部检查器与 DOC-T01
  共用。检查器段里再写 `states`/`db_sha256` 会被拒绝并提示改写位置，段的 `schema_version` 升到 2。
- `devices`：按位号的官方脚表（准确 MPN/封装、身份出处、`pinout_complete`、逐脚名称与角色）。
  角色增加 `nc`（手册标 NC/DNU）。原来只在 `decoupling.devices` 里，只有去耦用。

检查器清单的 `context` 改为“共享声明 + 本检查器段”的意图片段，改版与结果校验据此重建清单；
合并旧计划时逐检查器比较清单（原来只比 I²C 与去耦两个）。

### 4.2 计划变化

- DOC-T01 逐声明的装配状态一项（`DOC-T01.<状态>`），未声明时保留一项待补 `intent.assemblies`。
- 声明了脚表的位号：DEV-D02 附官方/符号双向差集，脚表完整时为 READY（原来一律待核）；
  DEV-D05 附未接网的官方脚与“标 nc 却接了网”的脚。两者都是待核清单，不是结论。
- 装配状态项（对象含 `assembly`）在改版影响里按全局依赖处理。

推荐工作条件（DEV-C05）没有放进 `intent.devices`：工作范围属于资料证据，放在第三步的
DEV-E02 证据计算里，意图只写设计工况。

### 4.3 验证

- 全部单元测试通过（新增：一份装配声明喂给 9 个检查器、装配状态错位提示、脚表驱动的 DEV-D02/DEV-D05）。
- 电路评测集 166 例对照 07238d3 基线逐例一致，零回归。
