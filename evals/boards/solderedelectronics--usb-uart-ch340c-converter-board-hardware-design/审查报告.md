## 发现的错误

### F01　S1选3.3V时，U1的V3没有与VCC相连

**P1 必需功能可能不达标**　电路错误　第1页　U1、S1、C2　功能电路 USB-K1

db U1.16=VCC_OUT，S1.3=+3V3，U1.4只接C2.1；WCH CH340 3C p3/5要求3V3时V3与VCC同接外部3V3。

- **问题**：db U1.16=VCC_OUT，S1.3=+3V3，U1.4只接C2.1；WCH CH340 3C p3/5要求3V3时V3与VCC同接外部3V3。
- **后果**：3.3V档不能得到原厂规定的工作保证，USB/UART运行和恢复不受保证；不声称实物必坏。

![U1的V3仅接C2到地，VCC接可切换轨。](record/evidence/figures/F01-actual-chip.png)

图：现状。U1的V3仅接C2到地，VCC接可切换轨。


![S1公共端2选择VUSB或+3V3。](record/evidence/figures/F01-actual-switch.png)

图：现状。S1公共端2选择VUSB或+3V3。


![原厂分别规定3V3和5V模式的V3/VCC接法。](record/evidence/figures/F01-reference.png)

图：原厂参考。原厂分别规定3V3和5V模式的V3/VCC接法。

- **怎么改**：重新设计切换：固定U1供电并给UART独立电平转换，或用有明确模式表的联动切换同时满足V3/VCC两档接法；不可永久短接V3/VCC后仍输入5V。

| 改哪里 | 现在 | 改成 |
|---|---|---|
| U1/S1和UART接口电源模式 | S1仅切U1.VCC，V3固定只接电容 | 按已确认模式采用固定U1供电加独立电平转换，或联动处理V3/VCC |

- **怎么验证**：对两档分别导出网表，追U1.4/.16到供电与返回，核选择动作表。（应：每档接法都符合CH340 p3/5，V3无5V直接供入路径，外端电平/掉电条款有对应结果。）

### 误报

1. **DEV-D02**：A01 原始SR文字：intent.device_kinds.D1: datasheet page + verbatim quote stating the device type (audit UNDECLARED)；逐条归因：DEV-D02.D1/D2/D3的pin_difference已给A/K两端空差集，但required_inputs仍要求颜色LED的手册类型。按规则DEV-D02两脚快速通道及commodity-floors可独立关闭针表；额定/光学另核。 建议：scripts/plan_board.py:plan_coverage / _two_terminal_package：两脚A/K+两端封装的DEV-D02去掉无关datasheet-kind依赖；保留极性/BOM额定及真正身份冲突。
2. **PWR-C09**：A02 原始SR文字：按本状态器件条款分别核对直接供电/返回段的数量、容量组合及有效容量要求；串联边界另一侧电容不计本段；替代接法需适用依据，标称总量不代替保证容量；逐条归因：K1的VBUS和K3的VCC触点因POWER类型触发PWR-T03/D02/C09/C10共8项；本端无源连接器不是IC，USB体电容在SIG-C05/PWR-C13已有覆盖。 建议：scripts/decoupling.py:Inventory.groups / role：在未核验手册的回退路径也采用字段一致的无源连接器身份排除IC旁路；不排除源端USB入口电容总额审查。
3. **PWR-C23**：A03 原始SR文字：PoE 与适配器等双源供电时，切换过程不超出当前电源能力，无反灌；适配器并联方式与所需隔离一致；逐条归因：K1经F1到VUSB再经U2为+3V3，S1选择二者；README称输出电压。没有第二个已许可来源，K4/K3可反供的风险归PRO-D04，不能直接当独立电源。 建议：scripts/plan_circuits.py:subject_precondition / plan_subjects；scripts/catalog.py:SUBJECT_REQUIRES：区分端口可馈入候选与已声明独立来源；只有独立源及切换机制成立才展开PWR-C23，反供仍保留。
4. **PRO-C07**：A04 原始SR文字：集成通路 eFuse 按手册规定条件核短路行为，超条件不得免判；过压钳位的持续过压后果与功能要求相符；要求确定掉电状态时输出有放电路径；逐条归因：PRO-C07.POWER-PROTECTION-K4.C3对象起于C3/F1，板上无eFuse/load_switch；该规则描述eFuse短路/过压失效，不能把任意POWER_PROTECTION都当eFuse。 建议：scripts/plan_circuits.py:subject_precondition / plan_subjects；scripts/catalog.py:SUBJECT_REQUIRES：要求核验的eFuse/load_switch控制器或等价有源断流拓扑才问PRO-C07；F1仍做PRO-C08/01/05/09。
5. **PWR-A01**：A05 原始SR文字：VCC_OUT: 板上无来源，经 ['K3.4'] 由外部供电；输入保护按 PRO 规则另核；逐条归因：lint INFO称VUSB经K4.3、VCC_OUT经K3.4外部供电且板上无来源；真实K1→F1→VUSB，S1选择VUSB/+3V3→VCC_OUT。INFO本身不是设计缺陷，但来源断言错误。 建议：scripts/checkers/powertree.py:PowerTree._search / source_of：沿实际F1和SPDT公共端分状态追踪源，输出触点只作未确认外部馈入候选；不把高阻/未上电路径冒充供电。
