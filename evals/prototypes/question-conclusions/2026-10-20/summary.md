# 一期（UART 链路，局部同口径）结果

范围：试点板 UART-XLAT、UART-DBG 两个功能电路，计划 12 行。合并规则沿用原型现状（电路按规则成题，状态并入一题）。

- A 组：试点台账补齐 b9fbef2 要求的方面判定（5 条 judgement）后，`derive_rows` + `validate_review` 有效。
- B 组跑了三版：arm-b（首轮）、arm-b2（跨电路合并 + 按状态拆）、arm-b3（数值结论按区间由机器推出 + 四条防过严约束，现行）。

## 现行：arm-b3（区间推结论 + 防过严）

规则：
- 数值输入都写保证范围（min–max）；机器在各角点算出结果范围。最不利角点满足判据才算通过，最有利角点也不满足才算不通过，介于两者之间是判不了。审查者写的结论与推出的不一致即报错。
- 条款标来源：DATASHEET / STANDARD / REQUIREMENT / PRACTICE / ASSUMPTION。
- 新增第四类检查"不过严"（STRICTNESS），代码如下：
  - FAIL_NOT_PROVEN：最有利角点仍通过，却判不通过。
  - FAIL_ON_ASSUMED_LIMIT：判不通过的限值来自审查者假定。
  - FAIL_ON_ASSUMED_POINT：判不通过依赖审查者假定的单个点值，而不是范围。
  - DUPLICATE_DEFECT：同一改法记成两个缺陷；正确写法是 `fix.same_as` 指向第一条。
  - SEVERITY_ABOVE_CLASS：等级高于后果类的上限。
  - REQUIREMENT_GRADED：需求没定的"判不了"被评了等级。需求没定的条目不评级、不阻塞定稿。
- 可查里补了单位和单调：
  - 输入按单位换算到国际单位计算，结果换回判据单位；
  - 受限算式做量纲检查（DIMENSION_MISMATCH），不认识的单位报 UNIT_UNKNOWN；
  - 范围内部抽样，结果超出角点范围报 NON_MONOTONIC。

结果（5 题、7 条结论、7 条条款，4779 字；复算 5 处，网表事实 6 条；有效）：

| 结论 | 状态 | 结果 | 推出的范围与余量 |
|---|---|---|---|
| SIG-C07 | esp-reset | 不通过 P1 | U6.35 被抬到 3.8–5.25 V，对 3.5–3.7 V；最有利角点仍超 0.1 V |
| SIG-C07 | run | 判不了（P1，找厂家） | 低电平 0–1.1 V 对 0.8–0.85 V；取决于 1N5819 在 0.3 mA 下的 VF |
| SIG-C08 | esp-reset | 不通过，改法同 SIG-C07 | 与 C07 同一缺陷，只计一次 |
| SIG-C08 | run | 通过 | 注入 0–10 µA，对惯例底线 30 µA |
| SIG-C09 | — | 通过 | 上升 220–1100 ns，对 8680 ns |
| SIG-D08、SIG-T04 | — | 通过 | 网表事实 6 条 |

与 A 组相比：
- 真缺陷相同，都是一个 P1。
- A 组在有效记录里留着两处 B 组不允许的判断：
  - SIG-C08 复位态按审查者自定的"允许注入 0 mA"判不通过（过严）；
  - run 态按 VF 典型值 0.2 V 判通过（过松）。
- B 组把前者并进了 C07 的缺陷，把后者改为判不了，并写明缺什么数据、找谁要。

16–18 三项，补检查之前的原型（提交 336012d）全部判为有效。第 16 项按原来的写法，0.03 A 的限值会让注入量放宽 1000 倍。

第 11 项在 A 组的注入方式：把余量改写成"最坏角点"算出的值。A 只看余量为负、有 fail 项，无从知道有利角点。

角点法的前提：算式对每个输入单调。机器在范围内部抽三个点检测，抽样点之间的转折仍可能漏掉，这一部分留给抽查。
补上单位与单调检查后，arm-b3 的 7 条结论原样通过，结果不变。

## 不能据此下结论的地方

1. 两组都是同一执行者完成的，不是盲测。召回、过严、token 都没有有效数据；两组的 P1 都沿用了试点结论。
2. A 第 8 项未拦，部分原因是 `review_scope` 让局部审查不必回答范围外的行；整板审查时 lint 行要求回答。
3. B 的字数少，有一部分是信息本身少了：A 的发现项带现象、场景、根因、分步改法、复验，B 只有一句改法加复验条件。可读性没测。
4. 记录条数 0.47 只是勉强达标，而局部范围看不出行数膨胀；按设计，整板二期才是关键。

## B 组暴露的摩擦，以及修后的 b2

首轮（arm-b）有两处摩擦：

- 同一判断按电路各出一题：SIG-C07、SIG-T04 在 UART-DBG 和 UART-XLAT 各写一条一样的结论（7 条里 2 条重复）。
- 状态合并后，一题跨 run（通过）与 esp-reset（不通过），结论记 FAIL，run 态的通过只能写进 notes，机器不核。
  这也是一种过严：run 态被一起记成了不通过。

原型改了两处（测试先行，手工变异 4 处均被杀死）：

1. `plan_to_questions.py`：同一规则、器件与网络完全相同的电路行合成一题（`subject.circuits` 列出各电路）；
   对象不同的照常分开，没有器件/网络锚点的不合并。
2. `conclusions_check.py`：结论可以带 `states`，在各状态结论不同时把一题按状态拆开写；
   这些结论合起来每个状态恰好覆盖一次（漏了报 UNANSWERED，重了报 DUPLICATE_CONCLUSION，不是本题的状态报 UNKNOWN_STATE）。
   拆不拆由审查者决定，结论相同时仍写一条结论，不强制拆。疑点按题回应一次：任一条结论不通过或回应了它即可。

| | arm-b | arm-b2 |

| 问题 | 7 | 5 |

结论数没变：省掉的 2 条重复结论，换成了 run 态的 2 条通过结论，而这两条的依据现在能被复算。
记录条数比值仍是 7/15 = 0.47。整板问题数只从 196 降到 194，所以合并规则对整板帮助很小，
行数膨胀主要来自器件级规则和需求条目（README 第 3 条）。

b2 新暴露的一处：run 态 C07 通过，依据是 VF ≤ 0.2 V（小电流下的典型值），esp-reset 态取的却是 0–0.6 V。
两个状态用的 VF 口径不同。结论把这个假定写进了条款 K-ASSUME，所以能看出来；
A 组只在 judgement 文字里写"≈ 0.7 V"，看不出来。这一点留给抽查：按设计，机器不判断条款是否适用。
