# 按设计准则度量 SR 检出力

在仓库根目录运行（Python 标准库，无网络、无需 KiCad）：

```sh
python3 -B evals/detection/run.py
```

默认重跑种子离线语料、典型电路、KiCad 原生回放，写本目录 `RESULTS.md`。
所有中间文件在 `/tmp/codex-work/sr-detection/run-*`，退出自动清理。耗时约三分钟。
`--work` 可指定任务临时目录；请仍放在 `/tmp/codex-work/` 下。
复用已有结果（路径分别对应上游 `--out`、`--json`、`--out`）：

```sh
python3 -B evals/detection/run.py \
  --seeded /tmp/codex-work/sr-detection/seeded/results.json \
  --typical /tmp/codex-work/sr-detection/typical.json \
  --replay /tmp/codex-work/sr-detection/replay/results.json
```

可用 `--output` 指定报告路径。复用数据不验证它确由当前技能生成，使用者须确认被测 checkout；报告保留输入 SHA256。
运行错误、未分类发现或 KiCad 字段不一致返回 1；已有漏报、已知误报仍生成报告，不把它们变成运行错误。
这是一份度量报告，不新增或改变 SR 审查流水线的入口和判据。

## 数从哪来

| 来源 | 归属与计数 | 限制 |
|---|---|---|
| seeded_bench | 每个 board/defect/site 一个正例；targets 经 `catalog.BASIS` 去重映射；auto 任一目标命中即检出 | 203 个假设注入位点，不是 203 个经独立确认的真实电气缺陷；其他规则发现、计划 pointed 均不算目标命中 |
| typical_circuits | 调用原基准 judge 产生的每条分类结果，按规则映射 BASIS | expected 是真实问题或正确线索，201 个正例不能都称真实缺陷 |
| known_defects.json（在电路评测集 `已知缺陷/`，见 `evals/eval_set.py`） | 人工整理台账与 audits 中有审查来源的事件；按具体语义窄映射 | 是历史结果，不是本次自动运行结果；不把一条事件中的行数当缺陷数 |
| kicad_replay_bench | 当前默认约定下字段一致/偏差/不一致总数单列 | 不具有设计缺陷真值，不能换算成电气命中 |
| input_bench | 展示仓库存档的 2026-10-07 import_after 4/4 | 未获得冻结作者输入，不重新运行；仅导入完整性 |
| consistency_bench | 明示没有仓内评分记录 | 一致性不判对错，即使有结果也不直接计检出 |
| mutation、rule_contracts | 排除 | 代码变异杀死率和合成触发合同不是设计缺陷检出率 |

`bench_coverage.py` 按自动规则统计真实板正例；这里复用同样的种子、典型来源，但不把其“有正例”当成本次命中。
`BASIS`、共用准则库、原基准答案与所有电气判据保持原样。

## 命中、漏报和误报

- **命中**：种子位点新增且点名位点的任一目标规则；典型正例 `DETECTED`；历史 `caught=true`。
- **漏报**：种子正常执行但无目标自动发现；典型正例 `MISSED`；历史明确记载漏检的 `caught=false`。
- **误报**：应通过的典型负例仍出现，即 `KNOWN_FALSE_ALARM` 或 `FALSE_ALARM_BACK`。原板基线发现数不算误报。
- **负例通过**：`FIXED` 或 `FALSE_ALARM_GONE`。后者可能使上游维护门失败，但对检出度量是正确消警。
- **未知**：历史无可判定结果，`caught="unknown"`；不把分歧、补证、修了代码或 pytest 通过当作检出证据。
- **运行错误、未分类**：单列，不能猜成漏报或误报。种子原板执行失败也保留错误记录。

每个准则按 `(来源, 用例身份, 准则)` 去重。同一个缺陷映射到多条准则时各计一次，所有准则列相加得到的是**归属次数**，不等于唯一缺陷数。
替代目标规则抓到同一注入缺陷即算命中，不因另一条目标没触发再算漏报。
BASIS 是规则与准则的关联：例如 TVS 审查线索出现在 PRO-E02，并不证明浪涌、温度等每个参数已经核算。
因此表里的命中只能称关联正例命中，不能称逐条准则完成了独立验证。没有 BASIS 的用例逐组保留，不能静默丢弃或靠相似词硬配。

## 历史清单的证据边界

每项包含 `id, source, criteria, sr_rules, caught, note`，另有 `kind`：
`electrical` 是有裁决或明确数值违规的电气真缺陷；`review_process` 是真实审查暴露的工具/执行问题；
`rule_audit` 是条文/桌面审计发现。`source` 为仓内文件和精确小节标题（` :: ` 分隔），脚本校验标题实际存在。
`caught` 记录 note 所述历史审查/漏报侧；不是当前版本的结论。同一物理错误不因台账多次提到重复收录。

本轮整理 53 项（6 项电气、37 项过程、10 项规则审计），不宣称穷尽台账中的所有子问题。
台账中单纯重命名、架构决定、无审查事实的用户偏好没有当缺陷录入。SR-B01…B06 按已存在编号分项；
R6/R7 仅有不同判断而无已确认真值的技术争议没有算成电气缺陷；NTC/压敏分类缺口不硬配浪涌准则。
历史误报纠正以过程事件保留 unknown，当前误报数只来自本次典型负例，以免历史与现值混计。

## 这张表不说明什么

无已知缺陷或正例的准则单独列出；它们的检出力完全未知，不表示检查无效。
“有检查但未在真缺陷上验证”仅看 `electrical` 历史记录的已确认结果，不把注入假设或正确线索升级为真缺陷。
历史 `false` 不证明当前版本仍漏；当前自动层命中也不证明专家审查、全部工况、动态/热/PCB/实测覆盖或设计准出。
样本偏斜、BASIS 的粗映射、未映射的自动规则、重叠的典型/种子板，均使整体准确率没有可靠含义。
不能按零命中、零样本或规则数多少直接砍检查；先补独立真缺陷及相邻合法反例，再讨论检查是否重复或无效。
