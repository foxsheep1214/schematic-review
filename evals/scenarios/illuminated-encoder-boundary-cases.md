# Illuminated encoder assemblies and evidence boundaries

Human paired cases from official sparkfun/Rotary_Encoder_Breakout-Illuminated@340b6eaf4db65f28a62819535cf20a27ea37afab, v10, plus explicitly versioned official encoder and Uno evidence. Originals, full primary ledger, disagreements and calculations remain in the calibration archive. These cases supplement existing G1–G7; they change no electrical criterion or automatic finding.

| Evidence | Correct disposition | Paired counterexample |
|---|---|---|
| One board offers mutually exclusive RGB common-anode and RG common-cathode footprints | Trace the selected assembly, LED/button COMMON and separate quadrature C; keep both original net partitions | Do not assume both encoders fitted, merge C/COMMON globally, or infer common polarity from README when original symbols and applicable drawings contradict it |
| RGB physical pins and RG physical pins differ; a header also has its own numbered order | Cross-check function, exact color-code row, mounting-side view and footprint geometry; current GR drawing maps 1 common, 2 green, 3 red, 4 switch | Do not reverse the numeric pin map, choose the neighboring RG color row for a GR part, or apply an old COM-10596-specific recipe to current COM-15140 without qualification |
| Passive breakout has no LED resistors; explicit Arduino recipe connects each color directly to GPIO; official maker confirms no internal limit | Assess the omitted per-color current limit in that actual recipe, while retaining valid externally driven uses of the passive body | Do not condemn every resistor-free breakout, assume GPIO is a constant-current source, or infer built-in resistance from ambiguous LED “5V” text |
| Contact current, push-switch current and LED current appear in different sections | Keep separate limits and conditions for each physical function | Contact 5mA or switch 10mA does not establish LED IF; old RG red/green ratings do not establish RGB or a different current RG MPN |
| Applicable RGB2021 each-phase minimum0.5mA; Uno internal RPU20–50kohm at5V gives0.10–0.25mA | Record a version-bound guaranteed-operating-condition FAIL for that specified branch; retain the circuit/model/date and actual pull configuration | Do not call known undercurrent “unknown host,” claim every unit necessarily misses counts, or transfer a minimum to legacy RG that only states a rated current |
| Current RG drawing proves functions, but electrical table belongs to another legacy MPN | Use the drawing for the narrow pin/geometry claim; obtain actual branch electrical guarantees or select a qualified compatible part | Do not mark current RG current/temperature PASS using legacy RVF limits; a real supplier gap is different from an available page not read |
| Bounce/phase guarantees have supply, load, speed, initial/aged conditions; firmware recommends optional capacitors | Check the promised operation and selected decode/bias/debounce conditions, retaining initial and endurance limits | No universal mandatory0.1uF, invented sampling guarantee, or transfer of a1rev/s test to every hand rotation; a timing check remains applicable when an actual example promises counting |
| Original direct contacts/LEDs have no off-state isolation; specified example uses one host supply domain | Trace reset/Hi-Z and powered-off/external-drive paths; restrict actual external drive or qualify injection/reverse limits | No invented shutdown component, universal Ioff guarantee, or complete exemption merely because the MCU is external |
