# RS232 电荷泵：供电组合、身份与接口成对判例

来源：[SparkFun MAX3232 Breakout v11](https://github.com/sparkfun/MAX3232_Breakout/tree/a622b6bf9c8cedb17b93a7e8bec73c2f4ea1efc2)，CC BY-SA4.0；原始单板 SCH/BRD 同 commit，7电气件、36物理节点、16网。作者产品/README是来源证据，未提供该revision绑定的带载/温度测试。原件不改，右栏为本地合成分支，不能当作者实际使用错误。

主参数来源：[TI MAX3232 SLLS410O June2021](https://www.ti.com/lit/ds/symlink/max3232.pdf)，p3/4–6/9–13；交叉核对：[ADI/Maxim 19-0273 Rev10 May2019](https://www.analog.com/media/en/technical-documentation/data-sheets/max3222-max3241.pdf)，Table2及MAX3232专属脚表/条件。TI原PDF本地归档，ADI官方PDF网页读取成功、本地下载超时如实记录；未用合册其他型号的SHDN/EN等功能。原件未绑定实装厂商/温度后缀，两个候选分支的共同偏离不等于全“generic MAX3232”家族或每个实物必然失败。

|---|---|

| SIG-E02/T01/T03：C1+/−、C2+/−是飞跨端，V+/−是内部储能，物理终点均证明无差分数据收发器。保留9条自动名称假设并有据判NA，转实际电荷泵检查。 | 仅凭P/N、+/−命名判数据对会误报。若另一真实电路出现实际两端差分驱动/接收器，须再适用电平/端接/全链路规则；电荷泵例不能成为名称全局豁免。 |
| DEV-D01/D04：VALUE=MAX3232，库deviceset=MAX232；嵌入description明确允许3V MAX3232 generic，SOIC16物理表兼容。模板名差不是已证实错型；实际MPN分支仍局部待核。 | 去掉明确兼容记录或真正不兼容的供电/脚义/封装证据时重新核身份，不因“同16脚”自动PASS。TI MAX3232CDR只能作为受控克隆候选，不能写成原件实装。 |
| SIG-C07/T04：逻辑DIN允许合适5V输入，不代表3V供电ROUT能驱动任意5VCMOS。TI ROUT最低VCC−0.6V@−1mA，3V时2.4V。四链按实际DIN/DOUT、RIN/ROUT和两次电压反相核方向。 | 明确外部5V CMOS VIH=3.5V时直连ROUT无保证裕量，应FAIL该指定系统；原裸模块无此peer不造系统缺陷。也不把DB9/“TX”名称当所有线缆针序。 |
| PWR-D02/DEV-C01：C3 V+返回GND是原厂允许接法；C4为非极性陶瓷。库已声明25V、+80/−20%，不能发明“无耐压/公差”待核；实际偏压/温度/功能容量仍按用途核。 | 硬套“V+储能只能接VCC”或“负轨电容必反极性”会误报。换成真实极性元件时须核正负端实际端差；额定25V不自动证明功能容量，也不强加无来源的C5最低Ceff。 |
| RST-T03/T04、SIG-D08：MAX3232无SHDN/EN；主动远端、逻辑host掉电、非零爬升和短路条款各自审视。TI限时/功耗短路条件不能换成另一厂商的连续短路保证；器件HBM不等于板级IEC。 | 要求任意host掉电不反灌，却只持输入耐压/绝限，不能PASS Ioff；合册其他型号关断真值表也不能补。未声明这种完整系统目标的裸板保留接口约束，不推定全部工况绝对安全。 |
| G2/G7：JP2的M10 description明确Header10、1X10 pad、十个实际角色；NO_PART=1支持不装header而直接焊线，pad/信号仍存在。四项connector规则手动补齐。 | 只看JP前缀或NO_PART就省掉端点检查会漏检；也不能一律把所有JP变connector。当前HEADER-NxM自动识别未扩展到M10，需人工确认并保留证据，不宣称本判例提高自动命中。 |
