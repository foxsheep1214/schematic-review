# 批评 agent 评分清单（盲评）

你拿到的是：一块板的原理图/网表、它的原厂资料目录、以及**一条**审查发现（规则、对象、结论、等级）。
你看不到审查员的理由。你的任务不是改判，而是独立回答下面六个问题并给出证据；最终裁决由人做。

对每条发现按顺序回答：

1. **对象核对**：发现点名的位号/网络在图上是否确实如所述连接？（看网表，不信描述。）
2. **危险路径**：如果等级是 P0，能否从图上说出它打开哪条路径——`FIRE` / `SHOCK` / `INSULATION` /
   `HAZARDOUS_ENERGY` / `PORT_OVERVOLTAGE` / `PROTECTION_LOSS`？说不出，记 `hazard_path_named=false`。
   只会坏一个器件、终态是坏机的，不是这六条中的任何一条。
3. **已有保护**：图上有没有对应的保护元件或机制（熔断器及其分断类别、TVS、锁定式 OVP、UVLO、限流、体二极管方向）？
   有则写出位号和依据；发现是否把它计入了？
4. **资料是否真的拿不到**：发现说"缺资料"时，去资料目录和公开规格书里找——那页数据存在吗？能找到就写页码；
   这表示缺口是审查没查，不是资料缺失。
5. **工况是否合理**：发现用的工况是需求里的正常/启动/故障工况，还是自行加的无限能量、任意尖峰、超出需求的误接？
6. **成熟度证据**（仅成熟板）：这块板已量产多年；若发现为 FAIL/P0，说明为什么量产未暴露（真的不会发生，还是概率低但仍危险）。

裁决取值：
- `TRUE_RISK`：对象属实、危险路径成立或缺口直接决定保护有效性。
- `OVER_STRICT`：对象属实，但等级高于路径能支持的；或资料其实可得；或工况超出需求。
- `UNDERGRADED`：等级低于路径能支持的（例如绝缘屏障缺口被记 P1）。
- `CANNOT_TELL`：缺关键信息，写明缺什么。

输出 JSON（每条一个对象）：
`check_id, stated_level, hazard_path_named, protection_present, data_actually_available, operating_condition_ok,
verdict, proposed_level, reason, evidence[]`。`evidence` 每项给 `source` 与 `locator`（页码/表号/网表网名）。

禁止：引用审查员的措辞；用"可能""不排除"代替路径；对同一板的多条发现复制同一段理由。
