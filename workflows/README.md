# 审查工作流

`sr-review.js` 是把审查流水线交给独立 agent 执行的编排脚本（Claude Code 的 workflow）。它不含审查规则：每一步做什么、关卡是什么，仍以 `SKILL.md` 的步骤表和 `references/step-*.md` 为准。脚本只规定三件事：

- 五个步骤各用一个新的上下文执行，只读 `SKILL.md`、流水线总览和本步的细则。
- 每步做完由另一个上下文实际运行本步的关卡命令，通过才进下一步；没过就把错误原文交回本步处置，超过限定轮数停下并报告卡在哪一步。
- 状态只记在审查工作目录里。缺只有人能给的东西（资料、需求澄清、设计未定项的决定）时停下，返回要问的问题；补齐后用 `start` 从那一步接着做。

## 怎么用

在 Claude Code 里让它运行这个工作流（按文件路径，或把本文件链接到项目的 `.claude/workflows/` 后按名称 `sr-review`），参数：

| 参数 | 含义 |
|---|---|
| `workdir` | 审查工作目录的绝对路径，全部产物写在这里 |
| `inputs` | 一段话说明输入在哪里：需求文件、原理图/网表/BOM、资料目录；被审对象是设计工作流的交付目录时写该目录的路径 |
| `revision` | 可选。改版复审时，上一轮审查工作目录的路径 |
| `start` | 可选。从第几步开始（1–5） |

返回 `status`：`complete`（报告在 `workdir/审查报告.md`）、`needs_input`（附 `questions`）、`blocked`（附卡住的步骤和关卡错误）。

## 与设计工作流的关系

审查和设计是两个独立的工作流，各由自己的 agent 执行，不在同一个上下文里往复。两者只通过文件交接：设计交付目录是审查的输入（读哪些、不读哪些见 `references/workflow-handoff.md`）；审查报告是设计改版的输入。改版由人发起，另开一次设计运行，改完再另开一次带 `revision` 的审查运行。
