# 审查工作流

`sr-review.js` 是把审查交给独立 agent 执行的编排脚本（Claude Code 的 workflow）。它不含审查规则：怎么审、怎么复核，以 `references/quick-review.md` 为准。脚本只规定谁做哪一段：

- 器件不超过 `quick_limit` 个：一位审查员审全板，另一个上下文的复核人独立复核。
- 器件更多：先分区，各区审查员和一位整板审查员并行审，复核人合成报告并独立复核。
- 缺只有人能给的东西（资料、需求澄清）时停下，返回要问的问题。

## 怎么用

在 Claude Code 里让它运行这个工作流（按文件路径，或把本文件链接到项目的 `.claude/workflows/` 后按名称 `sr-review`），参数：

| 参数 | 含义 |
|---|---|
| `workdir` | 审查工作目录的绝对路径，全部产物写在这里 |
| `inputs` | 一段话说明输入在哪里：需求文件、原理图/网表/BOM、资料目录；被审对象是设计工作流的交付目录时写该目录的路径 |
| `revision` | 可选。改版复审时，上一轮审查工作目录的路径 |
| `mode` | 可选。`auto`（默认，按器件数选）、`quick`、`zones` |
| `quick_limit` | 可选。快审的器件数上限，默认 40 |

返回 `status`：`complete`（报告在 `workdir/审查报告.md`）、`needs_input`（附 `questions`）、`blocked`（附原因）。

## 与设计工作流的关系

审查和设计是两个独立的工作流，各由自己的 agent 执行，不在同一个上下文里往复。两者只通过文件交接：设计交付目录是审查的输入（读哪些、不读哪些见 `references/workflow-handoff.md`）；审查报告是设计改版的输入。改版由人发起，另开一次设计运行，改完再另开一次带 `revision` 的审查运行。

改了脚本后，同一个会话里按名称调用的仍是会话启动时读到的版本：新开会话，或按脚本文件路径运行。
